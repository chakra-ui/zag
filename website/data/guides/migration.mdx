---
title: Migration Guide
description: Upgrading your project from Zag v1 to v2
---

Most v2 changes are additive, so you can upgrade one machine at a time. This
guide lists every breaking change by package. If a package you use isn't listed,
it upgrades without code changes.

> Still on v0? Follow the [v0 to v1 guide](https://zagjs.com/guides/migration)
> first.

## Upgrade the packages

Update every `@zag-js/*` package together. Machines and framework adapters share
one version, so mixing v1 and v2 packages isn't supported.

```bash
npm install @zag-js/react@next @zag-js/dialog@next
```

## Select and Combobox

`role="listbox"` moves from the content part to a new `list` part. Wrap the
items in `getListProps()` inside `getContentProps()`.

```tsx
<div {...api.getContentProps()}>
  <div {...api.getListProps()}>{/* items */}</div>
</div>
```

- `composite` is replaced by `popupType: "listbox" | "dialog"`. Migrate
  `composite: false` to `popupType: "dialog"`.
- Combobox: `scrollContentToTop` is renamed `scrollToTop`.
- `aria-controls` now points to the list id.
- Select: scroll arrows render inside the content instead of the positioner.

## Listbox

`role="listbox"` moves to a new `list` part, which is now the focus target and
carries `aria-activedescendant`.

```tsx
<div {...api.getContentProps()}>
  <ul {...api.getListProps()}>{/* items */}</ul>
</div>
```

If you virtualize the list, attach the scroll ref to the list element, since
`scrollIntoView` now targets it.

## Tabs

The `composite` prop is replaced by `virtualFocus`, and the boolean is inverted.

```diff
- tabs.machine({ composite: false })
+ tabs.machine({ virtualFocus: true })
```

## Popover

The `portalled` prop and `api.portalled` are removed. Portalling is detected
automatically.

```diff
- const service = useMachine(popover.machine, { id, portalled: true })
- const Wrapper = api.portalled ? Portal : Fragment
+ <Portal>
```

## Pin Input

`count` is now required. The machine no longer counts the inputs in the DOM.

```diff
  pinInput.machine({
    id: "pin",
+   count: 4,
  })
```

## Tags Input

`editable` now defaults to `false`. Set it to keep inline editing of tags.

```diff
+   editable: true,
```

## Avatar

`api.setSrc` is removed. Update `src` on the image you render instead.
`api.setLoaded()` and `api.setError()` are unchanged.

```diff
- api.setSrc(nextSrc)
+ imageEl.src = nextSrc
```

## Carousel

Three props are renamed.

| v1           | v2            |
| ------------ | ------------- |
| `slideCount` | `count`       |
| `autoplay`   | `autoPlay`    |
| `padding`    | `itemSpacing` |

## Tree View

```diff
- api.getCellProps(nodeProps)
+ api.getNodeCellProps(nodeProps)
```

## Toggle and Toggle Group

- Toggle group uses toggle-button semantics in every mode: `role="group"` and
  `aria-pressed`, with no radio roles and no `aria-checked`.
- `data-state="on|off"` is removed from toggle and toggle group. Style with
  `data-pressed`.
- `data-focus` is removed from toggle group parts. Use `:focus-visible` and
  `:focus-within`.

```diff
- screen.getByRole("radio", { checked: true })
+ screen.getByRole("button", { pressed: true })
```

## Floating Panel and Image Cropper

Handle naming is the same across both machines now.

- Floating panel: `ResizeTriggerProps.axis` is `placement`, `data-axis` is
  `data-placement`, and `resizeTriggerAxes` is `resizeTriggerPlacements`.
  `ResizeTriggerAxis` is removed; use `HandlePosition`.
- Image cropper: `HandleProps.position` is `placement`, `data-position` is
  `data-placement`, and `handles` is `placements`.

## Async List

Filter and sorting state are generic. The machine takes four type parameters,
`Item, Filter, Sorting, Cursor`, instead of two.

```diff
- asyncList.machine as asyncList.Machine<Item, string>
+ asyncList.machine as asyncList.Machine<Item, string, SortDescriptor<Item>, string>
- async load({ signal, cursor, filterText, sortDescriptor }) {
+ async load({ signal, cursor, filter, sorting }) {
```

| v1                      | v2                 |
| ----------------------- | ------------------ |
| `initialFilterText`     | `initialFilter`    |
| `initialSortDescriptor` | `initialSorting`   |
| `api.setFilterText()`   | `api.setFilter()`  |
| `api.sort()`            | `api.setSorting()` |
| `api.filterText`        | `api.filter`       |
| `api.sortDescriptor`    | `api.sorting`      |
| `api.sorting` (boolean) | `api.isSorting`    |
| `api.loading`           | `api.isLoading`    |
| `api.empty`             | `api.isEmpty`      |

## Behavior changes

These aren't API changes, but code that relies on the old behavior needs a look.

- **Hover Card:** the `closing` state is now `open.closing`.
- **Number Input:** `onValueInvalid` fires as the out-of-range value is entered,
  not on blur. The scrubber no longer creates its cursor element; render the
  `scrubberCursor` part with `getScrubberCursorProps()`.
- **Color Picker:** `getGamutOverlay()` replaces the `gamutOverlay` property.

## For adapter and library authors

- `@zag-js/dismissable`: `trackDismissableElement` requires `onLayerChange`.
  Apply the emitted layer index, nesting and pointer-blocking state in your
  render output.
- `@zag-js/rect-utils`: `resizeRect`, `AffineTransform`, `compassDirectionMap`,
  `oppositeDirectionMap` and `ScalingOptions` are removed.
- `@zag-js/core`: `isEqual` compares functions by reference and only reads an
  object's own properties.
