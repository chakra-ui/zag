---
title: Migration Guide
description: Upgrading your project from Zag v1 to v2
---

Most v2 changes are additive, so you can upgrade one machine at a time. This
guide lists every breaking change, starting with a rename table you can work
through as a checklist.

> Still on v0? Follow the [v0 to v1 guide](https://zagjs.com/guides/migration)
> first.

## Upgrade packages

Update every `@zag-js/*` package together. Machines and framework adapters share
one version, so mixing v1 and v2 packages isn't supported.

```bash
npm install @zag-js/react@next @zag-js/dialog@next
```

Some adapters need a newer framework:

- **Solid:** `solid-js` and `@solidjs/web` `>=2.0.0-rc.19`
- **Preact:** `preact` `>=11`. `preact/compat` is no longer needed.

## Run the codemod

The codemod applies most of this guide for you: selectors in stylesheets,
templates, Tailwind classes and tests, and prop and api renames. It lists what
it can't rewrite with a file and line, including props whose default changed.

```bash
npx @zag-js/codemod@next v2 src
```

Add `--dry-run` to see the changes as a diff first. It won't overwrite files
with uncommitted changes, so commit before you run it. Run your type checker
afterwards; the remaining errors point at the sections below.

## Data attributes

Every part now renders one attribute, `data-{scope}-{part}`, in place of
`data-scope`, `data-part` and `data-ownedby`. Its value is the machine's id.

```diff
- [data-scope="dialog"][data-part="trigger"] { ... }
+ [data-dialog-trigger] { ... }

- document.querySelector('[data-scope="dialog"][data-part="content"]')
+ document.querySelector("[data-dialog-content]")
```

State attributes like `data-state`, `data-focus` and `data-disabled` are
unchanged, except in
[toggle, toggle group and toolbar](#toggle-toggle-group-and-toolbar).

If you build on the anatomy API, `parts.X.attrs` is a function that takes the
machine id, and each part exposes the attribute name as `attr`.

```diff
- ...parts.trigger.attrs
- "data-ownedby": scope.id,
+ ...parts.trigger.attrs(scope.id)
```

## Layering

Zag no longer sets a `z-index`. Move it from the content to the positioner.

```diff
- [data-popover-content] {
+ [data-popover-positioner] {
-   z-index: 1400;
+   z-index: calc(1400 + var(--layer-index));
  }
```

`--z-index` is removed. The floating panel needs the same rule to bring the
focused panel to the front. See [Layering](/guides/styling#layering).

## Accordion

Arrow, `Home` and `End` navigation between triggers is removed, along with
`loopFocus`, following the WAI-ARIA accordion pattern. Users move between
triggers with `Tab`.

`collapsible` now defaults to `true`. Set it to `false` to keep one item open.

```diff
  accordion.machine({
    id: "faq",
-   loopFocus: true,
+   collapsible: false,
  })
```

## Async list

The machine takes four type parameters, `Item, Filter, Sorting, Cursor`, instead
of two. See [Renames](#renames) for the props and API.

```diff
- asyncList.machine as asyncList.Machine<Item, string>
+ asyncList.machine as asyncList.Machine<Item, string, SortDescriptor<Item>, string>
- async load({ signal, cursor, filterText, sortDescriptor }) {
+ async load({ signal, cursor, filter, sorting }) {
```

## Avatar

`api.setSrc` is removed. Update `src` on the image you render instead.

```diff
- api.setSrc(nextSrc)
+ setSrc(nextSrc) // your own state, passed to <img src={src} />
```

## Combobox

`role="listbox"` moves from the content part to a new `list` part, and
`aria-controls` points to it. Wrap the items in `getListProps()`.

```tsx
<div {...api.getContentProps()}>
  <div {...api.getListProps()}>{/* items */}</div>
</div>
```

`disableLayer` is replaced by `inline`. An inline combobox is always open, isn't
positioned or dismissable, and doesn't call `onOpenChange`.

```diff
  combobox.machine({
-   open: true,
-   disableLayer: true,
+   inline: true,
  })
```

## Listbox

`role="listbox"` moves to a new `list` part, which is now the focus target and
carries `aria-activedescendant`.

```tsx
<div {...api.getContentProps()}>
  <ul {...api.getListProps()}>{/* items */}</ul>
</div>
```

If you virtualize the list, attach the scroll ref to the list element.

## Number input

The scrubber no longer creates its cursor element. Render the `scrubberCursor`
part.

```tsx
<div {...api.getScrubberCursorProps()} />
```

## Pin input

`count` is required. The machine no longer counts the inputs in the DOM.

```diff
  pinInput.machine({
    id: "pin",
+   count: 4,
  })
```

`blurOnComplete` is removed. Move focus somewhere useful in `onValueComplete`.

```diff
-   blurOnComplete: true,
+   onValueComplete() {
+     document.getElementById("verify")?.focus()
+   },
```

`selectOnFocus` is removed. A focused input always selects its character, so
delete the prop.

`sanitizeValue` is renamed `normalizeValue` and also runs on typed text. Pasted
codes already drop dashes and spaces, so delete a function that only stripped
those.

## Popover

`portalled` and `api.portalled` are removed. Portalling is detected
automatically.

```diff
- const Wrapper = api.portalled ? Portal : Fragment
- <Wrapper>
+ <Portal>
```

## Radio group and tabs indicator

The indicator no longer sets inline transition styles, and the
`--transition-property`, `--transition-duration` and
`--transition-timing-function` variables are removed. Add the transition in your
CSS, and skip it while `data-instant` is set.

```css
[data-tabs-indicator]:not([data-instant]) {
  transition: all 150ms ease;
}
```

## Scheduler

Dates in the scheduler API are `CalendarDateTime` instead of `DateValue`, since
the scheduler always works in wall-clock time. Convert zoned or date-only values
before passing them in.

```diff
- import { parseZonedDateTime } from "@internationalized/date"
- start: parseZonedDateTime("2026-03-02T09:00[America/New_York]")
+ import { parseDateTime } from "@internationalized/date"
+ start: parseDateTime("2026-03-02T09:00")
```

## Select

`role="listbox"` moves from the content part to a new `list` part, and
`aria-controls` points to it. Wrap the items in `getListProps()`. Scroll arrows
render inside the content instead of the positioner.

```tsx
<div {...api.getContentProps()}>
  <div {...api.getListProps()}>{/* items */}</div>
</div>
```

## Slider

The array props for thumb labels are replaced by functions, matching
`getAriaValueText`.

```diff
  slider.machine({
-   "aria-label": ["Minimum price", "Maximum price"],
+   getAriaLabel: ({ index }) => (index === 0 ? "Minimum price" : "Maximum price"),
  })
```

## Steps

Steps are defined by an `items` array and addressed by string `value` instead of
index.

```diff
  steps.machine({
-   count: 3,
-   defaultStep: 0,
+   items: [{ value: "cart" }, { value: "shipping" }, { value: "gift", optional: true }],
+   defaultValue: "cart",
  })
```

| v1                                          | v2                                                              |
| ------------------------------------------- | --------------------------------------------------------------- |
| `count`                                     | `items`                                                         |
| `step` / `defaultStep`                      | `value` / `defaultValue`                                        |
| `onStepChange`                              | `onValueChange`                                                 |
| `onStepComplete`                            | `onComplete`                                                    |
| `isStepValid(index)`                        | `invalid` on the item                                           |
| `isStepSkippable(index)`                    | `optional` on the item, plus `skipTrigger`                      |
| `onStepInvalid`                             | `onNavigationBlocked` (`reason`, `blockedBy`)                   |
| `api.setStep(index)`                        | `api.setValue(value)`                                           |
| `api.isCompleted`                           | `api.complete`                                                  |
| `step === count` (completed screen)         | `value === steps.COMPLETE`                                      |
| `getContentProps({ index: count })`         | `getContentProps({ value: steps.COMPLETE })`                    |
| `api.isStepValid` / `isStepSkippable`       | `api.getItemState({ value })`                                   |
| `{ index }` in part props                   | `{ value }`                                                     |
| `itemState.incomplete`                      | `[data-incomplete]`, or not `current`, `completed` or `skipped` |
| `itemState.first` / `itemState.last`        | `index === 0` / `index === api.count - 1`                       |
| `itemState.skippable` / `isValid()`         | `itemState.optional` / `!itemState.invalid`                     |
| `ids.triggerId(index)` / `contentId(index)` | `(value) => string`                                             |
| `--percent`                                 | `--steps-percent`                                               |

## Tabs

`composite` is replaced by `virtualFocus`, with the boolean inverted.

```diff
- tabs.machine({ composite: false })
+ tabs.machine({ virtualFocus: true })
```

`onValueChange` and `onFocusChange` details are typed as nullable. `value` is
`null` after a `deselectable` tab is deselected, and `focusedValue` is `null`
when focus leaves the tab list.

## Tags input

`editable` defaults to `false`. Set it to keep inline editing of tags.

```diff
+   editable: true,
```

## Toast

Render the new `content` part around the title, description and other content.
The toast's height follows it, and without it the height stops updating after
mount.

```tsx
<div {...api.getRootProps()}>
  <div {...api.getContentProps()}>{/* title, description */}</div>
</div>
```

Toasts now swipe to dismiss. Pass `swipeDirections: []` to the store or a toast
to turn it off.

## Toggle, toggle group and toolbar

- Toggle group uses toggle-button semantics in every mode: `role="group"` and
  `aria-pressed`, with no radio roles.
- `data-state="on|off"` is removed. Style with `data-pressed`.
- `data-focus` is removed from toggle group and toolbar parts. Use
  `:focus-visible` and `:focus-within`.

```diff
- screen.getByRole("radio", { checked: true })
+ screen.getByRole("button", { pressed: true })
```

## Behavior changes

These compile without changes but behave differently.

- **Hover card:** the `closing` state is now `open.closing`. `matches("open")`
  still works; only code matching `"closing"` needs updating.
- **Number input:** `onValueInvalid` fires as the out-of-range value is entered,
  not on blur.
- **Pin input:** a paste drops spaces and characters that don't match `type` or
  `pattern` instead of being rejected, and reports them through
  `onValueInvalid`.
- **Table of contents:** `multiple` defaults to `false`, so only the topmost
  visible heading is active. Pass `multiple: true` for the v1 behavior.
- **Toast:** `--duration` is the toast's total duration, not the time remaining.
- **Forms:** a read-only radio group or file upload now submits its value. A
  disabled slider or angle slider is left out of the form.
- **Tags input:** `onHighlightChange` reports the tag's value, not its DOM id.

## Adapter authors

- `@zag-js/dismissable`: `trackDismissableElement` requires `onLayerChange`.
  Apply the emitted layer index, nesting and pointer-blocking state in your
  render output.
- `@zag-js/rect-utils`: `resizeRect`, `AffineTransform`, `compassDirectionMap`,
  `oppositeDirectionMap` and `ScalingOptions` are removed.
- `@zag-js/utils`: `isEqual` compares functions by reference and only reads an
  object's own properties.
