Lets users pick a color from a color area, channel sliders or swatches, with
full control over the UI

<Resources pkg="@zag-js/color-picker" />

<Showcase id="ColorPicker" />

**Features**

- Supports custom color area
- Supports RGBA, HSLA, HEX, HSBA, **OKLab**, and **OKLCH** formats
- Optional **sRGB gamut overlay** on the 2D area when using OKLab/OKLCH
  (`getGamutOverlay`, `getGamutOverlayProps`, anatomy part `gamutOverlay`)
- Supports channel inputs and sliders
- Supports mouse, touch, and keyboard interactions
- Supports form submission and reset events
- Supports named CSS colors

### Value changes

When the user selects a color using the color picker, the `onValueChange` and
`onValueChangeEnd` events will be fired.

- `onValueChange` — Fires in sync as the user selects a color
- `onValueChangeEnd` — Fires when the user stops selecting a color (useful for
  debounced updates)

<Example id="ColorPickerValueChange">

```tsx
const [current, send] = useMachine(colorPicker.machine, {
  onValueChange: (details) => {
    // details => { value: Color, valueAsString: string }
  },
  onValueChangeEnd: (details) => {
    // details => { value: Color, valueAsString: string }
  },
})
```

</Example>

### Custom color format

By default, the color picker's output format is `rgba`. You can change this
format to either `hsla` or `hsba` with `format`.

When this is set, the `value` and `valueAsString` properties of the
`onValueChange` event will be updated to reflect the new format.

<Example id="ColorPickerFormat">

```tsx
const [current, send] = useMachine(colorPicker.machine, {
  format: "hsla",
  onValueChange: (details) => {
    // details => { value: HSLAColor, valueAsString: string }
  },
})
```

</Example>

### Wide gamut colors

The **2D color area** stays **HSBA** (saturation × brightness, **hue** on the
third-axis slider) for a familiar control surface, even when the **output
format** is OKLab or OKLCH.

Use **`api.getGamutOverlay(props?)`** for SVG path data (`path`,
`labelPosition`) that draws the **sRGB gamut boundary** in that HSB view. The
boundary is computed like Chrome DevTools (HSV interpreted in a wide working
space vs sRGB). Pass the **same** `props` to **`getAreaProps`**,
**`getGamutOverlay`**, and **`getGamutOverlayProps`**—including optional
`xChannel` / `yChannel` overrides and optional **`pixelRatio`** (defaults to
`globalThis.devicePixelRatio` in the browser for sharper curves on retina).

**`api.isInSrgbGamut`** is `true` when the current color lies inside the sRGB
cube in linear RGB space. When `false`, your OKLab/OKLCH **string** may still be
wide-gamut while **hex** or 8-bit **RGBA** outputs **clamp**—use this flag for
badges, tooltips, or warnings.

const [current, send] = useMachine(colorPicker.machine, {
  defaultFormat: "hsla",

</Example>

### Controlled format

Use `format` and `onFormatChange` to control the active format.

<Example id="ColorPickerControlledFormat">

```tsx
const [current, send] = useMachine(colorPicker.machine, {
  format,
  onFormatChange(details) {
    setFormat(details.format)
  },
})
```

</Example>

### Disabled state

Set `disabled` to `true` to disable user interaction.

<Example id="ColorPickerDisabled">

```tsx
const [current, send] = useMachine(colorPicker.machine, {
  disabled: true,
})
```

</Example>

### Controlled open

Use `open` and `onOpenChange` to control whether the picker is visible.

<Example id="ColorPickerOpenControlled">

```tsx
const [current, send] = useMachine(colorPicker.machine, {
  open: true,
  onOpenChange: (details) => {
    // details => { open: boolean, value: Color, reason?: OpenChangeReason }
  },
})
```

</Example>

`details.reason` says what caused the change.

| Reason             | Meaning                                     |
| ------------------ | ------------------------------------------- |
| `trigger-click`    | The trigger was pressed                     |
| `item-select`      | A swatch was selected                       |
| `escape-key`       | The user pressed `Esc`                      |
| `interact-outside` | The user pressed outside the color picker   |
| `focus-outside`    | Focus moved outside                         |
| `script`           | Changed programmatically, such as `setOpen` |

You can also leverage the `api.setOpen(...)` method to control the open and
closed state of the color picker.

### Positioning

Use `positioning` to control popup placement and collision behavior.

<Example id="ColorPickerPositioning">

```tsx
const [current, send] = useMachine(colorPicker.machine, {
  positioning: { placement: "bottom-start", gutter: 8 },
})
```

</Example>

### Initial focus

Use `initialFocusEl` to choose which element receives focus when the popup
opens.

<Example>

```tsx
const [current, send] = useMachine(colorPicker.machine, {
  initialFocusEl: () => document.getElementById("alpha-input"),
})
```

</Example>

### Inline rendering

Set `inline` to render the picker without a trigger and popup.

<Example id="ColorPickerInline">

```tsx
const [current, send] = useMachine(colorPicker.machine, {
  inline: true,
})
```

</Example>

channel individually. You can do this using an input element or a slider
element, or both.

To support this, use the `getChannelInputProps(...)` to show the channel inputs.

> Note: Make sure you only render the channel inputs that match the `format` of

### Localized channel values

Set `locale` to format the channel values that screen readers announce on the
area and sliders. It defaults to `"en-US"`.

```tsx
const service = useMachine(colorPicker.machine, {
  locale: "de-DE",
})
```

Use `api.getChannelValueText(channel)` to show the same formatted value, like
`80 %` for alpha in German.

The eye dropper tool is a native browser feature that lets users pick a color
from a current page's canvas. To support this, use the
`getEyeDropperTriggerProps(...)`.

> **Note:** The eye dropper tool only works in Chrome and Edge browsers

### Form usage

To use the color picker in a form, set `name` and render the hidden input.

<Example>

  name: "color-preference",
