A scheduler lays events out on a calendar — a day or week time grid, a month
grid, a year overview, an agenda list, or a resource timeline. You render the
markup; the machine handles navigation, layout math, and pointer gestures for
moving, resizing, and creating events.

> **Good to know**: Dates are
> [`CalendarDateTime`](https://react-spectrum.adobe.com/internationalized/date/CalendarDateTime.html)
> values from `@internationalized/date`. The scheduler works in wall-clock time,
> so an event at `9:00` renders at `9:00` regardless of `timeZone`.

**Features**

- Day, week, month, year, agenda, and timeline views.
- Drag to move and resize events, with snapping to `slotInterval`.
- Click or drag across empty slots to create events.
- Drop constraints, and drops from outside the scheduler.
- Recurring events from RFC 5545 `RRULE` strings.
- Resource scheduling, as columns or as timeline rows.
- All-day events laid out as continuous bars across days.
- Overlapping events packed side by side, with conflict detection.
- Locale, time zone, and RTL aware.

## Usage

Import the package:

```tsx
import * as scheduler from "@zag-js/scheduler"
```

These are the key exports:

- `machine` - State machine logic.
- `connect` - Maps machine state to JSX props and event handlers.
- `getToday` - Returns today as a `CalendarDateTime` for a given time zone.
- `expandRecurringEvents` - Expands recurring events within a date range.

The scheduler doesn't own your events. Pass them in with `events`, and update
your own state when the user moves or resizes one.

Here's a week view with a time grid:

```tsx
import * as scheduler from "@zag-js/scheduler"
import { normalizeProps, useMachine } from "@zag-js/react"
import { useId, useState } from "react"

export function Scheduler() {
  const [events, setEvents] =
    useState<scheduler.SchedulerEvent[]>(initialEvents)

  const service = useMachine(scheduler.machine, {
    id: useId(),
    defaultView: "week",
    events,
    onEventDrop(details) {
      setEvents((prev) =>
        prev.map((e) =>
          e.id === details.event.id
            ? { ...e, start: details.newStart, end: details.newEnd }
            : e,
        ),
      )
    },
  })

  const api = scheduler.connect(service, normalizeProps)

  return (
    <div {...api.getRootProps()}>
      <div {...api.getHeaderProps()}>
        <button {...api.getPrevTriggerProps()}>‹</button>
        <button {...api.getTodayTriggerProps()}>Today</button>
        <button {...api.getNextTriggerProps()}>›</button>
        <span {...api.getHeaderTitleProps()}>
          {api.visibleRangeText.formatted}
        </span>
      </div>

      <div {...api.getColumnHeadersProps()}>
        {api.visibleDays.map((date) => (
          <div key={date.toString()} {...api.getColumnHeaderProps({ date })}>
            {api.formatWeekDay(date)} {date.day}
          </div>
        ))}
      </div>

      <div {...api.getGridProps()}>
        <div {...api.getGridRowProps()}>
          <div {...api.getTimeGutterProps()}>
            {api.hourRange.hours.map((hour) => (
              <div key={hour.value} {...api.getHourLabelProps({ hour })}>
                {hour.label}
              </div>
            ))}
          </div>

          {api.visibleDays.map((date) => (
            <div key={date.toString()} {...api.getDayColumnProps({ date })}>
              {api.hourRange.hours.map((hour) => (
                <div key={hour.value} {...api.getHourLineProps({ hour })} />
              ))}
              <div {...api.getCurrentTimeIndicatorProps({ date })} />

              {api.getEventsForDay(date).map((event) => (
                <div key={event.id} {...api.getEventProps({ event })}>
                  {event.title}
                  <div
                    {...api.getEventResizeHandleProps({ event, edge: "end" })}
                  />
                </div>
              ))}

              <div {...api.getDragOriginProps({ date })} />
              <div {...api.getDragPreviewProps({ date })}>
                {api.dragState?.event.title}
              </div>
            </div>
          ))}
        </div>
      </div>
    </div>
  )
}
```

The day column, events, current-time indicator, and drag overlays are positioned
with inline styles. Give the grid a height and the day columns
`position: relative`, and the rest falls into place.

### Defining events

Each event needs an `id`, a `title`, and `start` / `end` values.

```tsx
import { CalendarDateTime } from "@internationalized/date"

const initialEvents: scheduler.SchedulerEvent[] = [
  {
    id: "standup",
    title: "Standup",
    start: new CalendarDateTime(2026, 4, 13, 9, 0),
    end: new CalendarDateTime(2026, 4, 13, 9, 30),
    color: "#3b82f6",
  },
  {
    id: "offsite",
    title: "Team offsite",
    start: new CalendarDateTime(2026, 4, 14),
    end: new CalendarDateTime(2026, 4, 16),
    allDay: true,
  },
]
```

Other optional fields:

- `allDay` - Renders the event in the all-day row instead of the time grid. Its
  `end` is inclusive.
- `color` - Exposed as the `--event-color` CSS variable on the event.
- `disabled` - The event can't be dragged or resized.
- `recurrence` - A recurrence rule. See [Recurring events](#recurring-events).
- `resourceId` - The resource the event belongs to.
- `payload` - Any metadata. It's passed back in every callback.

### Setting the visible hours

Use `dayStartHour` and `dayEndHour` to trim the time grid, and `slotInterval`
(`15`, `30`, or `60` minutes) to set the snapping step for drags and slot
selection. The defaults are `0`, `24`, and `30`.

```tsx
const service = useMachine(scheduler.machine, {
  id: useId(),
  dayStartHour: 8,
  dayEndHour: 18,
  slotInterval: 15,
})
```

`api.hourRange.hours` follows these bounds, with a localized `label` and a
`percent` position for each hour.

### Switching views

The scheduler supports six views: `day`, `week`, `month`, `year`, `agenda`, and
`timeline`. The default is `week`. Use `defaultView` to set the initial view,
and render a view switcher with `getViewSelectProps` and `getViewItemProps`.

```tsx
const views: scheduler.ViewType[] = ["day", "week", "month"]

<div {...api.getViewSelectProps()}>
  {views.map((view) => (
    <button key={view} {...api.getViewItemProps({ view })}>
      {api.getViewText(view)}
    </button>
  ))}
</div>
```

Each view controls how far `goToNext` and `goToPrev` move:

| View       | Visible range                   | Step    |
| ---------- | ------------------------------- | ------- |
| `day`      | One day                         | 1 day   |
| `week`     | One week                        | 1 week  |
| `month`    | The month, padded to full weeks | 1 month |
| `year`     | January to December             | 1 year  |
| `agenda`   | The date plus the next 30 days  | 30 days |
| `timeline` | One week, laid out horizontally | 1 week  |

The markup is yours, so render the layout that matches `api.view`.

### Controlled view and date

Use `view` with `onViewChange`, and `date` with `onDateChange`, to control what
the scheduler shows.

```tsx
import type { CalendarDateTime } from "@internationalized/date"

const [view, setView] = useState<scheduler.ViewType>("week")
const [date, setDate] = useState<CalendarDateTime>(scheduler.getToday())

const service = useMachine(scheduler.machine, {
  id: useId(),
  view,
  onViewChange(details) {
    // details => { view: ViewType }
    setView(details.view)
  },
  date,
  onDateChange(details) {
    // details => { date: CalendarDateTime }
    setDate(details.date)
  },
})
```

For uncontrolled usage, use `defaultView` and `defaultDate`. When `defaultDate`
is omitted, the scheduler starts on today.

### Programmatic navigation

Use the `api` to change the view or move the visible range.

```tsx
api.setView("month")
api.setDate(new CalendarDateTime(2026, 6, 1))
api.goToToday()
api.goToNext()
api.goToPrev()
```

`api.visibleRange` holds the raw `start` / `end` of the visible range, and
`api.visibleRangeText.formatted` holds a localized label for it, such as
`"Apr 12, 2026 – Apr 18, 2026"`.

### Moving and resizing events

Dragging an event fires `onEventDrop`, and dragging a resize handle fires
`onEventResize`. The scheduler only reports the new position — apply it to your
own events.

```tsx
const service = useMachine(scheduler.machine, {
  id: useId(),
  events,
  onEventDrop(details) {
    // details => { event, newStart, newEnd, allDay, delta, resource }
    setEvents((prev) =>
      prev.map((e) =>
        e.id === details.event.id
          ? {
              ...e,
              start: details.newStart,
              end: details.newEnd,
              allDay: details.allDay,
            }
          : e,
      ),
    )
  },
  onEventResize(details) {
    // details => { event, newStart, newEnd, edge }
    setEvents((prev) =>
      prev.map((e) =>
        e.id === details.event.id
          ? { ...e, start: details.newStart, end: details.newEnd }
          : e,
      ),
    )
  },
})
```

In `onEventDrop`, `allDay` tells you whether the event landed on the all-day
row, so dragging between the time grid and the all-day row can convert an event.
An all-day event dropped into the time grid gets a one-hour length. `delta`
holds how far it moved, as `{ days, minutes }`.

Render a resize handle per edge with `getEventResizeHandleProps`. An edge can't
be dragged past the other one, so a timed event never gets shorter than one
slot.

While a gesture is in progress, `api.dragState` holds the event, its predicted
`start` / `end`, and its `origin`. Render `getDragPreviewProps` and
`getDragOriginProps` in each day column to show where the event will land and
where it came from. Pressing `Escape` cancels the gesture.

### Locking events

Set `disabled` on an event to lock it. For finer control, use `canDragEvent` and
`canResizeEvent`.

```tsx
const service = useMachine(scheduler.machine, {
  id: useId(),
  events,
  canDragEvent: (event) => !event.payload?.locked,
  canResizeEvent: (event) => !event.payload?.fixedLength,
})
```

Set `disabled` on the scheduler to turn off dragging, resizing, and slot
selection in the time grid.

### Restricting where events can drop

Use `canDropEvent` to accept or reject a position. It receives the same details
as `onEventDrop`, and runs while the user drags.

```tsx
const service = useMachine(scheduler.machine, {
  id: useId(),
  events,
  canDropEvent({ event, newStart, newEnd }) {
    // keep events within business hours
    if (newStart.hour < 9 || newEnd.hour > 17) return false
    // and off other events
    return !events.some(
      (other) =>
        other.id !== event.id &&
        newStart.compare(other.end) < 0 &&
        newEnd.compare(other.start) > 0,
    )
  },
})
```

While the position is rejected, the event gets `data-invalid` and the root gets
`data-drop-invalid`. Releasing on a rejected position doesn't fire `onEventDrop`
or `onEventResize`.

### Listening for event clicks

Use `onEventClick` to open details or an edit dialog. It fires on click, and on
`Enter` or `Space` while the event has focus.

```tsx
const service = useMachine(scheduler.machine, {
  id: useId(),
  events,
  onEventClick(details) {
    // details => { event }
    openEditor(details.event)
  },
})
```

The clicked event gets `data-selected`.

### Creating events from a slot

Clicking or dragging across empty time fires `onSlotSelect`. A click selects one
slot of `slotInterval` minutes; a drag selects the range the pointer covered.

```tsx
const service = useMachine(scheduler.machine, {
  id: useId(),
  events,
  onSlotSelect(details) {
    // details => { start, end, allDay, action: "click" | "drag", resource }
    openCreateDialog({ start: details.start, end: details.end })
  },
})
```

The selection stays in `api.selectedSlot` until you clear it or start another
gesture. Render `getSelectedSlotProps` in each day column to highlight it, and
call `api.clearSelectedSlot()` when your dialog closes.

```tsx
<div {...api.getDayColumnProps({ date })}>
  {/* hour lines and events */}
  <div {...api.getSelectedSlotProps({ date })} />
</div>
```

To anchor a popover to the highlighted slot, use `api.getSelectedSlotEl()` as
the anchor element.

For a quick-create shortcut, use `onSlotDoubleClick`. It fires with
`{ start, end, allDay, resource }` and doesn't change `selectedSlot`.

### Rendering all-day events

All-day events render in a row above the time grid. Use `getAllDaySegments` to
lay each event out as one bar across the days it covers.

```tsx
<div {...api.getAllDayRowProps()}>
  <div {...api.getAllDayLabelProps()}>All day</div>
  {api.visibleDays.map((date, index) => (
    <div key={date.toString()} {...api.getDayCellProps({ date, allDay: true })}>
      {api
        .getAllDaySegments()
        .filter((segment) => segment.column === index)
        .map((segment) => (
          <div
            key={segment.event.id}
            {...api.getEventProps({
              event: segment.event,
              layout: "all-day",
              segment,
            })}
          >
            {segment.event.title}
          </div>
        ))}
    </div>
  ))}
</div>
```

Each segment carries `column`, `span`, and `level` (its stacking row), plus
`isStart` / `isEnd`, which are `false` when the bar is clipped by the visible
range. Only render a resize handle on an edge that isn't clipped.

Filter all-day events out of the time grid, since `getEventsForDay` returns both
kinds:

```tsx
api.getEventsForDay(date).filter((event) => !event.allDay)
```

To cap the row height, set `maxAllDayRows`. Bars past that level are hidden, and
`api.getAllDayOverflow()` returns `{ date, count }` per day for a "+N more"
label.

### Rendering the month view

Use `getMonthGrid` to get the weeks of the month, padded to six full weeks. Pass
`referenceDate` to `getDayCellProps` so days outside the month get
`data-outside`.

```tsx
<div>
  {api.getMonthGrid().map((week, weekIndex) => {
    const bars = api.getAllDaySegments(week)
    return (
      <div key={weekIndex}>
        {week.map((date, dayIndex) => {
          const timed = api.getEventsForDay(date).filter((e) => !e.allDay)
          return (
            <div
              key={date.toString()}
              {...api.getDayCellProps({ date, referenceDate: api.date })}
            >
              {date.day}
              {bars
                .filter((segment) => segment.column === dayIndex)
                .map((segment) => (
                  <div
                    key={segment.event.id}
                    {...api.getEventProps({
                      event: segment.event,
                      layout: "all-day",
                      segment,
                    })}
                  >
                    {segment.event.title}
                  </div>
                ))}
              {timed.slice(0, 2).map((event) => (
                <div
                  key={event.id}
                  {...api.getEventProps({ event, layout: "list" })}
                >
                  {event.title}
                </div>
              ))}
              {timed.length > 2 && (
                <button
                  {...api.getMoreEventsProps({ date, count: timed.length - 2 })}
                >
                  +{timed.length - 2} more
                </button>
              )}
            </div>
          )
        })}
      </div>
    )
  })}
</div>
```

Pass one week at a time to `getAllDaySegments(week)`, so bars break at the end
of each row. Use `api.getWeekDays()` for the weekday header labels.

Clicking a day cell fires `onSlotSelect` with `allDay: true` and the whole day
as the range.

### Rendering the year view

The year view is a set of twelve mini month grids. Use `getMonthGridProps`,
`getWeekRowProps`, and `getDayCellTriggerProps` to make the days keyboard
navigable. Render one `MiniMonth` per month, with `month` from `1` to `12`.

```tsx
function MiniMonth(props: { api: scheduler.Api; month: number }) {
  const { api, month } = props
  const reference = api.date.set({ month, day: 1 })
  return (
    <section>
      <h3>{api.getMonthName(reference)}</h3>
      <div {...api.getMonthGridProps({ date: reference })}>
        <div {...api.getWeekdayHeaderRowProps()}>
          {api.getWeekDays().map((day) => (
            <div key={day.long} {...api.getWeekdayHeaderCellProps({ day })}>
              {day.narrow}
            </div>
          ))}
        </div>
        {api.getMonthGrid(reference).map((week, weekIndex) => (
          <div key={weekIndex} {...api.getWeekRowProps()}>
            {week.map((date) => (
              <div
                key={date.toString()}
                {...api.getDayCellProps({ date, referenceDate: reference })}
              >
                <div
                  {...api.getDayCellTriggerProps({
                    date,
                    referenceDate: reference,
                  })}
                >
                  {date.day}
                </div>
              </div>
            ))}
          </div>
        ))}
      </div>
    </section>
  )
}
```

Use `onDayActivate` to react when a day is clicked, or activated with `Enter` /
`Space` — for example, to open that day in the day view.

```tsx
const service = useMachine(scheduler.machine, {
  id: useId(),
  defaultView: "year",
  onDayActivate(details) {
    // details => { date: CalendarDateTime }
    api.setDate(details.date)
    api.setView("day")
  },
})
```

`api.focusedDate` holds the day with keyboard focus. Use `api.setFocusedDate`
and `api.clearFocusedDate` to move or drop it.

### Rendering the agenda view

The agenda view lists events from the current date through the next 30 days. Use
`getAgendaGroups` to get them grouped by day and sorted by start.

```tsx
<div>
  {api.getAgendaGroups().map((group) => (
    <div
      key={group.date.toString()}
      {...api.getAgendaGroupProps({ date: group.date })}
    >
      <div {...api.getAgendaGroupTitleProps({ date: group.date })}>
        {api.formatLongDate(group.date)}
      </div>
      {group.events.map((event) => (
        <div key={event.id} {...api.getEventProps({ event, layout: "list" })}>
          {api.formatTimeRange(event.start, event.end)} {event.title}
        </div>
      ))}
    </div>
  ))}
</div>
```

### Recurring events

Add a `recurrence` with an RFC 5545 `RRULE` string. The scheduler expands it
into instances within the visible range.

```tsx
const events: scheduler.SchedulerEvent[] = [
  {
    id: "sync",
    title: "Weekly sync",
    start: new CalendarDateTime(2026, 4, 13, 10, 0),
    end: new CalendarDateTime(2026, 4, 13, 10, 30),
    recurrence: {
      rrule: "FREQ=WEEKLY;BYDAY=MO,WE;COUNT=16",
      exdate: [new CalendarDateTime(2026, 4, 15, 10, 0)],
    },
  },
]
```

- `rrule` - The rule. `FREQ` (`DAILY`, `WEEKLY`, `MONTHLY`, `YEARLY`),
  `INTERVAL`, `COUNT`, `UNTIL`, `BYDAY`, and `BYMONTHDAY` are expanded natively.
  Monthly rules support positional days such as `1MO` (first Monday) and `-1FR`
  (last Friday).
- `exdate` - Occurrences to skip.
- `dtstart` - The series start. Defaults to the event's `start`.

Each instance gets an id of the form `<id>:<index>`, and `api.events` holds the
expanded list. `maxRecurrenceInstances` caps the total (default `2000`).

Drag, resize, and `onEventClick` look events up by id in the `events` you pass,
so they don't fire for expanded instances.

#### Using a custom recurrence expander

Rules outside the native subset are passed to `expandRecurrence`. Use it to plug
in a full RRULE library. Without it, such events render once at their `start`.

```tsx
const service = useMachine(scheduler.machine, {
  id: useId(),
  events,
  expandRecurrence(event, range) {
    // return concrete instances of `event` between range.start and range.end
    return expandWithMyLibrary(event, range)
  },
})
```

To expand events outside the machine, use the `expandRecurringEvents` export:

```tsx
const instances = scheduler.expandRecurringEvents({
  events,
  range: { start, end },
})
```

### Scheduling against resources

Pass `resources` (people, rooms, equipment) and set `groupBy` to `"resource"` to
split each day into one column per resource. Assign events with `resourceId`.

```tsx
const resources: scheduler.SchedulerResource[] = [
  { id: "amelia", title: "Amelia Stone", color: "#6366f1" },
  { id: "brooke", title: "Brooke Chen", color: "#10b981" },
  { id: "room-b", title: "Room B", disabled: true },
]

const service = useMachine(scheduler.machine, {
  id: useId(),
  defaultView: "day",
  resources,
  groupBy: "resource",
  events,
})
```

Render `api.columns` instead of `api.visibleDays`. Each column has a `date` and,
when grouping by resource, a `resource`. Pass the column straight to the column
props, and use `getEventsForColumn` to scope events to it.

```tsx
<div {...api.getGridRowProps()}>
  <div {...api.getTimeGutterProps()}>{/* hour labels */}</div>
  {api.columns.map((column) => (
    <div
      key={`${column.date}:${column.resource?.id}`}
      {...api.getDayColumnProps(column)}
    >
      {api.getEventsForColumn(column).map((event) => (
        <div key={event.id} {...api.getEventProps({ event })}>
          {event.title}
        </div>
      ))}
      <div {...api.getDragPreviewProps(column)} />
    </div>
  ))}
</div>
```

`onSlotSelect`, `onSlotDoubleClick`, and `onEventReceive` include the `resource`
of the column the gesture happened in. `onEventDrop` includes the event's own
resource, looked up from its `resourceId`.

A resource's `color` is exposed as `--resource-color` on its columns. A
`disabled` resource rejects slot selection and drops, and its column gets
`data-disabled`.

### Rendering a timeline

The `timeline` view lays a week out horizontally, with one row per resource. Use
`getTimelineState` to get the `rows` and the day `slots`.

```tsx
const timeline = api.getTimelineState()

<div {...api.getTimelineProps()}>
  <div {...api.getTimelineHeaderProps()}>
    {timeline.slots.map((slot) => (
      <div key={slot.start.toString()} {...api.getTimelineSlotProps({ slot })}>
        {slot.label}
      </div>
    ))}
  </div>

  {timeline.rows.map((row) => (
    <div key={row.id} {...api.getTimelineRowProps({ row })}>
      <div {...api.getTimelineRowHeaderProps({ row })}>{row.title}</div>
      <div {...api.getTimelineTrackProps({ row })}>
        {api.getEventsForRow(row).map((event) => (
          <div
            key={event.id}
            {...api.getEventProps({ event, layout: "timeline" })}
          >
            {event.title}
          </div>
        ))}
      </div>
    </div>
  ))}
</div>
```

Without `resources`, the timeline has a single row holding every visible event.

### Dropping items from outside

Use `onEventReceive` to accept native drag-and-drop from outside the scheduler,
such as a backlog list. The day columns and the all-day row accept drops only
when this callback is set.

```tsx
const service = useMachine(scheduler.machine, {
  id: useId(),
  events,
  onEventReceive(details) {
    // details => { start, end, allDay, resource, data }
    const task = backlog.find((item) => item.id === details.data)
    if (!task) return
    setEvents((prev) => [
      ...prev,
      {
        id: task.id,
        title: task.title,
        start: details.start,
        end: details.end,
        allDay: details.allDay,
      },
    ])
  },
})

// the draggable item
<button
  draggable
  onDragStart={(event) => event.dataTransfer.setData("text/plain", task.id)}
>
  {task.title}
</button>
```

`data` is read from the drop's `dataTransfer` using `dataTransferFormat`, which
defaults to `"text/plain"`. A drop on the time grid gives one slot snapped to
`slotInterval`; a drop on the all-day row gives the whole day, with `start` and
`end` on the same date.

### Showing a work week

Set `workWeekOnly` to limit the week view to `workWeekDays` (default Monday to
Friday, as `[1, 2, 3, 4, 5]` where `0` is Sunday).

```tsx
const service = useMachine(scheduler.machine, {
  id: useId(),
  defaultView: "week",
  workWeekOnly: true,
  workWeekDays: [1, 2, 3, 4, 5],
})
```

### Highlighting conflicts

Timed events that overlap get `data-conflict`. Events in different resources are
checked separately. Use `api.hasConflict(event)` or
`api.getEventState(id).conflict` to read it in render.

### Customizing locale, time zone, and labels

- `locale` - Drives the week start and every formatter (default `"en-US"`).
- `timeZone` - Decides which day is today and drives the formatters. Defaults to
  the user's time zone.
- `startOfWeek` - Overrides the first day of the week (`0` is Sunday).
- `dir` - Set to `"rtl"` for right-to-left layouts.
- `translations` - Labels for the navigation triggers and view names.

```tsx
const service = useMachine(scheduler.machine, {
  id: useId(),
  locale: "de-DE",
  startOfWeek: 1,
  translations: {
    prevTriggerLabel: "Zurück",
    nextTriggerLabel: "Weiter",
    todayTriggerLabel: "Heute",
    viewSelectLabel: "Kalenderansicht",
    viewText: { day: "Tag", week: "Woche", month: "Monat" },
  },
})
```

Use the `api` formatters so your markup matches the locale and time zone:
`formatTime`, `formatTimeRange`, `formatLongDate`, `formatWeekDay`,
`formatDuration`, `getMonthName`, and `getMonthNames`.

### CSS variables

The root exposes a few variables you can use to build the grid:

- `--scheduler-columns` - The number of rendered columns (days, or days ×
  resources).
- `--scheduler-visible-days` - The number of visible days.
- `--scheduler-hour-count` - The number of hours in the time grid.

```css
[data-scheduler-grid-row] {
  display: grid;
  grid-template-columns: 60px repeat(var(--scheduler-columns), minmax(0, 1fr));
}

[data-scheduler-grid] {
  height: calc(var(--scheduler-hour-count) * 48px);
}
```

The all-day row sets `--scheduler-all-day-rows` to its number of stacked levels.
Set `--scheduler-all-day-bar-height` (default `19px`) to change the height of
each level.

## Accessibility

The time grid, the timeline, and each mini month grid use the `grid` role, with
rows, column headers, and cells. The header title is a polite live region, so
navigating announces the new range. Each day trigger is labelled with its full
date, whether it's today, and its event count, and only the focused day is in
the tab order.

Moving and resizing events is pointer-only. Use `onEventClick` to open an edit
dialog, so keyboard users can change an event's time.
