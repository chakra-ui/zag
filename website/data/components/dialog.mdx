A dialog is a window overlaid on the page, and while it's modal the content
behind it is inert

**Features**

- Supports modal and non-modal modes
- Focus is trapped and scrolling is blocked in the modal mode
- Provides screen reader announcements via rendered title and description
- Pressing `Esc` closes the dialog
- Supports multiple triggers sharing a single dialog instance

### Focus management

When the dialog opens, it focuses the first focusable element and keeps keyboard
focus inside the dialog.

To control what receives focus on open, pass `initialFocusEl`.

<Example id="DialogInitialFocus">

<CodeSnippet id="dialog/initial-focus.mdx" />

</Example>

Return `false` to open the dialog without moving focus. `Tab` and `Escape` still
work.

```tsx
const service = useMachine(dialog.machine, {
  id: useId(),
  initialFocusEl: () => false,
})
```

> In a modal dialog, content outside is `aria-hidden`. Leaving focus there means
> screen readers announce nothing on open. Use it for dialogs that appear
> without user intent, and prefer `data-autofocus` on an element inside when you
> only want to redirect focus.

To control what receives focus when the dialog closes, pass `finalFocusEl`.

### Modal vs non-modal

Set `modal` to `false` to allow interaction with content behind the dialog.

<Example id="DialogNonModal">

```tsx
const service = useMachine(dialog.machine, {
  modal: false,
})
```

</Example>

Use `api.modal` to skip the backdrop, since it would block interaction with the
page.

```tsx
{
  api.modal && <div {...api.getBackdropProps()} />
}
```

### Close on outside click

By default, the dialog closes when you click its overlay. You can set
`closeOnInteractOutside` to `false` if you want the modal to stay visible.

<Example id="DialogInteractOutside">

```tsx {2}
const service = useMachine(dialog.machine, {
  closeOnInteractOutside: false,
})
```

</Example>

You can also customize the behavior by passing a function to the
`onInteractOutside` callback and calling `event.preventDefault()`.

```tsx {2-7}
const service = useMachine(dialog.machine, {
  onInteractOutside(event) {
    const target = event.target
    if (target?.closest("<selector>")) {
      return event.preventDefault()
    }
  },
})
```

### Open state changes

When the dialog is opened or closed, the `onOpenChange` callback is invoked.

<Example id="DialogOpenChange">

```tsx {2-7}
const service = useMachine(dialog.machine, {
  onOpenChange(details) {
    // details => { open: boolean }
    console.log("open:", details.open)
  },
})
```

</Example>

### Escape to close

Set `closeOnEscape` to `false` if the dialog should not close on `Esc`.

<Example id="DialogEscape">

```tsx
const service = useMachine(dialog.machine, {
  closeOnEscape: false,
```

</Example>

### Scroll behavior

When the dialog is open, it prevents scrolling on the `body` element. To disable
this behavior, set `preventScroll` to `false`.

<Example id="DialogScroll">

```tsx {2}
const service = useMachine(dialog.machine, {
  preventScroll: false,
})
```

</Example>

### Alert dialog

The dialog supports both `dialog` and `alertdialog` roles. It uses `dialog` by
default. Set `role` to `alertdialog` for urgent actions.

That's it! Now you have an alert dialog.

<Example id="DialogAlert">

```tsx {2}
const service = useMachine(dialog.machine, {
  role: "alertdialog",
})
```

</Example>

> By definition, an alert dialog will contain two or more action buttons. We
> recommend setting focus to the least destructive action via `initialFocusEl`.

### Multiple triggers

A single dialog instance can be shared across multiple trigger elements. Pass a
`value` to `getTriggerProps` to identify each trigger.

<Example id="DialogMultipleTriggers">

```tsx
const users = [
  { id: "1", name: "Alice Johnson" },
  { id: "2", name: "Bob Smith" },
]

const service = useMachine(dialog.machine, {
  onTriggerValueChange({ value }) {
    // value is the id of the trigger that activated the dialog
    const user = users.find((u) => u.id === value) ?? null
    setActiveUser(user)
  },
})

const api = dialog.connect(service, normalizeProps)

return (
  <>
    {users.map((user) => (
      <button {...api.getTriggerProps({ value: user.id })}>
        Edit {user.name}
      </button>
    ))}
    {/* single shared dialog */}
    <div {...api.getBackdropProps()} />
    <div {...api.getPositionerProps()}>
      <div {...api.getContentProps()}>{/* ... */}</div>
    </div>
  </>
)
```

</Example>

When the dialog is open and a different trigger is activated, it switches
without closing. `aria-expanded` is scoped to the active trigger, and focus
returns to the correct trigger on close.

You can also read or set the active trigger programmatically:

```tsx
// Read the active trigger value
api.triggerValue // => string | null

// Set the active trigger value
api.setTriggerValue("2")
```

### Hidden label

If you do not render a title element, provide `aria-label`.

<Example>

```tsx
const service = useMachine(dialog.machine, {
  "aria-label": "Delete project",
})
```

</Example>

## Styling

### Scrollbar width

When `preventScroll` is enabled, Zag applies `--scrollbar-width` on the root
element. Use this CSS variable to keep fixed or sticky elements aligned when the
dialog opens and body scrolling is locked.

```css
.app-header {
  position: fixed;
  inset-inline-end: calc(1rem + var(--scrollbar-width, 0px));
}
```

### Nested dialogs

When dialogs are nested (a dialog opened from within another dialog), the layer
stack automatically applies data attributes to help create visual hierarchy.

- `data-nested` - Applied to nested dialogs
- `data-has-nested` - Applied to dialogs that have nested dialogs open
- `--nested-layer-count` - CSS variable indicating the number of nested dialogs

```css
/* Scale down parent dialogs when they have nested children */
[data-dialog-content][data-has-nested] {
  transform: scale(calc(1 - var(--nested-layer-count) * 0.05));
  transition: transform 0.2s ease-in-out;
}

/* Style nested dialogs differently */
[data-dialog-content][data-nested] {
  border: 2px solid var(--accent-color);
}

/* Create depth effect using backdrop opacity */
[data-dialog-backdrop][data-has-nested] {
  opacity: calc(0.4 + var(--nested-layer-count) * 0.1);
}
```
