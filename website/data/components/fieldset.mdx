Fieldset groups related form controls under a shared legend, so disabled state,
helper text and group errors apply to all of them at once

<Resources pkg="@zag-js/fieldset" />

<Showcase id="Fieldset" />

**Features**

- Renders a native `<fieldset>` with a stylable legend
- Supports helper text and group-level error text
- `disabled` cascades to descendant form controls (including `@zag-js/field`)
- `invalid` stays on the fieldset. Nested fields keep their own validity
- Wires `aria-labelledby` and `aria-describedby` for you

## Usage

<CodeSnippet id="fieldset/usage.mdx" />

Root props are meant for a native `<fieldset>`. That keeps browser disabled
inheritance and form semantics intact.

### Disabled state

Set `disabled` to disable every descendant control.

<Example id="FieldsetDisabled">

```tsx {3}
const service = useMachine(fieldset.machine, {
  id: useId(),
  disabled: true,
})
```

</Example>

```tsx
<fieldset {...api.getRootProps()}>
  <legend {...api.getLegendProps()}>Shipping</legend>
  {/* inputs, fields, checkboxes inside are disabled */}
</fieldset>
```

This uses the native `<fieldset disabled>` attribute. `@zag-js/field` (and other
Zag controls that track form state) observe that attribute and mirror
`data-disabled` on their own parts. This works through nested fieldsets too:
disabling an outer fieldset disables the controls in every fieldset inside it.

### Invalid state

Set `invalid` for a group-level error, such as "pick at least one option" on a
checkbox group.

<Example id="FieldsetInvalid">

```tsx {3}
const service = useMachine(fieldset.machine, {
  id: useId(),
  invalid: true,
})
```

</Example>

```tsx
<fieldset {...api.getRootProps()}>
  <legend {...api.getLegendProps()}>Notifications</legend>
  {/* options */}
  <span {...api.getErrorTextProps()}>Select at least one channel</span>
</fieldset>
```

Fieldset `invalid` does **not** mark nested fields invalid. Each `@zag-js/field`
keeps its own validity. Use fieldset invalid for the group message, and field
invalid for per-control messages.

While the fieldset is invalid, every `@zag-js/field` inside it adds the
fieldset's error text to its control's `aria-describedby`. Screen reader users
hear the group message when they move to any option, not only when they enter
the group.

### Helper text

<Example id="FieldsetHelperText">

```tsx
<fieldset {...api.getRootProps()}>
  <legend {...api.getLegendProps()}>Contact details</legend>
  <span {...api.getHelperTextProps()}>How can we reach you?</span>
  {/* fields */}
</fieldset>
```

</Example>

Helper text is always referenced from `aria-describedby`. Error text is only
referenced while the fieldset is invalid. The legend names the fieldset through
`aria-labelledby` only while it is rendered.

### Nesting fields

Compose with `@zag-js/field` for labeled controls inside the group.

<Example id="FieldsetNested">

```tsx
import * as field from "@zag-js/field"
import * as fieldset from "@zag-js/fieldset"

const fieldsetApi = fieldset.connect(fieldsetService, normalizeProps)
const fieldApi = field.connect(fieldService, normalizeProps)

<form>
  <fieldset {...fieldsetApi.getRootProps()}>
    <legend {...fieldsetApi.getLegendProps()}>Contact details</legend>
    <span {...fieldsetApi.getHelperTextProps()}>How can we reach you?</span>

    <div {...fieldApi.getRootProps()}>
      <label {...fieldApi.getLabelProps()}>
        Phone <span {...fieldApi.getIndicatorProps({ type: "required" })}>*</span>
      </label>
      <input {...fieldApi.getInputProps()} type="tel" name="phone" />
      <span {...fieldApi.getErrorTextProps()}>{fieldApi.errors[0]}</span>
    </div>

    <span {...fieldsetApi.getErrorTextProps()}>
      Contact details are incomplete
    </span>
  </fieldset>
</form>
```

</Example>

Disable the fieldset and the phone field's input gets `disabled` and
`data-disabled` without passing a prop into the field machine.

### Grouping

Use a fieldset when one legend labels several options. Keep each option's own
label next to the control.

<Example id="FieldsetRadios">

```tsx
<fieldset {...api.getRootProps()}>
  <legend {...api.getLegendProps()}>Backup schedule</legend>
  <span {...api.getHelperTextProps()}>Choose how often we save a copy</span>

  {options.map((option) => (
    <Option key={option.value} name="backup" {...option} />
  ))}

  <span {...api.getErrorTextProps()}>Pick a schedule</span>
</fieldset>
```

</Example>

Wrap each option in its own `@zag-js/field`, so the fieldset's error text
reaches every option:

```tsx
function Option(props: { name: string; value: string; label: string }) {
  const service = useMachine(field.machine, { id: useId() })
  const api = field.connect(service, normalizeProps)
  return (
    <div {...api.getRootProps()}>
      <input
        {...api.getInputProps()}
        type="radio"
        name={props.name}
        value={props.value}
      />
      <label {...api.getLabelProps()}>{props.label}</label>
    </div>
  )
}
```

The same pattern works with `@zag-js/radio-group` or `@zag-js/checkbox` as the
controls inside the fieldset. Put the group label on the legend, not on a field
label, when the accessible name applies to the whole set.

### Form libraries

Fieldset only needs `disabled` and `invalid` from a form library. Per-control
validation still belongs on each field (see the
[Field](/components/field#react-hook-form) docs).

<Example>

```tsx
const service = useMachine(fieldset.machine, {
  id: useId(),
  invalid: !!errors.channels,
  disabled: formState.isSubmitting,
})
```

</Example>

## Styling

### Disabled and invalid

```css
[data-fieldset-root][data-disabled] {
  opacity: 0.6;
}

[data-fieldset-root][data-invalid] {
  border-color: red;
}

[data-fieldset-error-text][hidden] {
  display: none;
}
```

`data-disabled` reflects this fieldset **or** an ancestor fieldset being
disabled. The native `disabled` attribute is only set from this fieldset's own
`disabled` prop, which is what the HTML spec expects for nested fieldsets.
