A toolbar groups a set of controls — buttons, toggle groups, menus, inputs —
into a single widget, like the formatting bar in a text editor. The toolbar
manages focus between them so the whole bar is one tab stop.

**Features**

- Acts as a single tab stop, with arrow keys moving focus between items.
- Remembers the last focused item when you tab away and back.
- Horizontal or vertical orientation, with right-to-left support.
- Disabled items can stay focusable so they remain discoverable.
- Composes with toggle group, menu, select, tooltip, number input and more.

## Usage

Import the toolbar package:

```tsx
import * as toolbar from "@zag-js/toolbar"
```

The toolbar package exports two key functions:

- `machine` - State machine logic.
- `connect` - Maps machine state to JSX props and event handlers.

Spread `getRootProps` on the container and `getItemProps` on each button. Every
item needs a unique `value`. Use `getGroupProps` to group related items and
`getSeparatorProps` to divide them.

```tsx
import * as toolbar from "@zag-js/toolbar"
import { normalizeProps, useMachine } from "@zag-js/react"
import { useId } from "react"

export function Toolbar() {
  const service = useMachine(toolbar.machine, { id: useId() })
  const api = toolbar.connect(service, normalizeProps)

  return (
    <div {...api.getRootProps()} aria-label="Formatting">
      <div {...api.getGroupProps({ value: "clipboard" })}>
        <button {...api.getItemProps({ value: "cut" })}>Cut</button>
        <button {...api.getItemProps({ value: "copy" })}>Copy</button>
        <button {...api.getItemProps({ value: "paste" })}>Paste</button>
      </div>

      <div {...api.getSeparatorProps()} />

      <a {...api.getLinkProps({ value: "history" })} href="/history">
        Edited 5m ago
      </a>
    </div>
  )
}
```

The root renders `role="toolbar"`. Give it an accessible name with `aria-label`
or `aria-labelledby`.

Arrow navigation runs across groups and separators in one flat sequence — groups
are for labelling and styling, not for separate focus stops.

### Vertical orientation

Set `orientation` to `"vertical"` to stack the items. Arrow navigation switches
to `ArrowUp` / `ArrowDown`, and `ArrowLeft` / `ArrowRight` do nothing.

```tsx {3}
const service = useMachine(toolbar.machine, {
  id: useId(),
  orientation: "vertical",
})
```

Separators take the opposite orientation of the toolbar, so a vertical toolbar
renders horizontal separators.

### Looping focus

By default, arrowing past the last item wraps to the first, and vice versa. Set
`loopFocus` to `false` to stop at the ends.

```tsx {3}
const service = useMachine(toolbar.machine, {
  id: useId(),
  loopFocus: false,
})
```

### Disabling the toolbar

Set `disabled` to disable every item and input at once. Links rendered with
`getLinkProps` are not affected.

```tsx {3}
const service = useMachine(toolbar.machine, {
  id: useId(),
  disabled: true,
})
```

Read `api.disabled` to forward the state to machines you compose inside the
toolbar.

### Disabled items

Pass `disabled` to `getItemProps`. By default, a disabled item stays focusable
and reachable with the arrow keys, so users can still discover it. It gets
`aria-disabled` instead of the native `disabled` attribute, which means clicks
still fire — guard your handler with `getItemState`.

```tsx
const pasteState = api.getItemState({ value: "paste", disabled: true })

<button
  {...api.getItemProps({ value: "paste", disabled: true })}
  onClick={() => {
    if (pasteState.disabled) return
    paste()
  }}
>
  Paste
</button>
```

Set `focusableWhenDisabled` to `false` to fully disable the item. It gets the
native `disabled` attribute and arrow keys skip it.

```tsx
<button
  {...api.getItemProps({
    value: "copy",
    disabled: true,
    focusableWhenDisabled: false,
  })}
>
  Copy
</button>
```

### Disabled groups

`getGroupProps({ disabled })` only sets `aria-disabled` and `data-disabled` on
the group. It does not disable the items inside, so pass it down yourself.

```tsx
const groupDisabled = true

<div {...api.getGroupProps({ value: "clipboard", disabled: groupDisabled })}>
  <button {...api.getItemProps({ value: "cut", disabled: groupDisabled })}>
    Cut
  </button>
  <button {...api.getItemProps({ value: "copy", disabled: groupDisabled })}>
    Copy
  </button>
</div>
```

### Composing with toggle group

Render a [toggle group](/components/toggle-group) inside the toolbar root to add
pressable options like bold / italic / underline. Its items join the toolbar's
arrow navigation — arrowing past the last toggle moves on to the next toolbar
item.

Inside a toolbar, the toggle group drops its own tab stop and leaves looping,
`Home` and `End` to the toolbar. Forward the toolbar's `disabled` and
`orientation` so both machines agree.

```tsx
import * as toggleGroup from "@zag-js/toggle-group"

function FormatGroup(props: { api: toolbar.Api }) {
  const { api: toolbarApi } = props
  const service = useMachine(toggleGroup.machine, {
    id: useId(),
    multiple: true,
    disabled: toolbarApi.disabled,
    orientation: toolbarApi.orientation,
  })
  const api = toggleGroup.connect(service, normalizeProps)

  return (
    <div {...api.getRootProps()}>
      <button {...api.getItemProps({ value: "bold" })} aria-label="Bold">
        B
      </button>
      <button {...api.getItemProps({ value: "italic" })} aria-label="Italic">
        I
      </button>
    </div>
  )
}

// inside the toolbar root
;<div {...api.getRootProps()} aria-label="Formatting">
  <FormatGroup api={api} />
  <div {...api.getSeparatorProps()} />
  <button {...api.getItemProps({ value: "link" })}>Link</button>
</div>
```

The toggle group detects the toolbar when it mounts, so render it inside the
toolbar root from the start.

### Composing with menus, selects and tooltips

To use another machine's trigger as a toolbar item, both machines must agree on
one DOM id. Pass `api.getItemId(value)` as the composed machine's trigger id,
then merge both sets of props onto the same button.

```tsx
import * as menu from "@zag-js/menu"
import { mergeProps } from "@zag-js/react"

function MoreActions(props: { api: toolbar.Api }) {
  const { api } = props

  const service = useMachine(menu.machine, {
    id: useId(),
    ids: { trigger: api.getItemId("more") },
  })
  const menuApi = menu.connect(service, normalizeProps)

  return (
    <>
      <button
        {...mergeProps(
          menuApi.getTriggerProps(),
          api.getItemProps({ value: "more" }),
        )}
      >
        More actions
      </button>
      {/* menu positioner and content */}
    </>
  )
}
```

While the menu is open, arrow keys move through the menu items. Closing it
returns focus to the trigger, and arrow keys move through the toolbar again.

The same pattern works for a select (`ids: { trigger }`), a tooltip
(`ids: { trigger }`), or a checkbox (`ids: { hiddenInput }`).

### Text inputs in a toolbar

Use `getInputProps` for an `<input>` item. Arrow keys move the caret inside the
field, and only move focus to the next item when the caret is already at the
start or end. `Home` and `End` stay inside the field. Focusing the input selects
its text.

```tsx
import * as numberInput from "@zag-js/number-input"

function ZoomInput(props: { api: toolbar.Api }) {
  const { api } = props

  const service = useMachine(numberInput.machine, {
    id: useId(),
    ids: { input: api.getItemId("zoom") },
    disabled: api.disabled,
    defaultValue: "100",
  })
  const numberApi = numberInput.connect(service, normalizeProps)

  return (
    <input
      aria-label="Zoom"
      {...mergeProps(
        numberApi.getInputProps(),
        api.getInputProps({ value: "zoom" }),
      )}
    />
  )
}
```

If the composed input handles an arrow key itself — like a number input in a
vertical toolbar handling `ArrowUp` / `ArrowDown` — the toolbar leaves focus
where it is.

A disabled input that stays focusable is rendered `readOnly`.

### Right-to-left support

Set `dir` to `"rtl"` to flip horizontal arrow keys: `ArrowLeft` moves to the
next item and `ArrowRight` to the previous one.

```tsx {3}
const service = useMachine(toolbar.machine, {
  id: useId(),
  dir: "rtl",
})
```

## Styling guide

Each part has a `data-toolbar-*` attribute you can target in CSS. Items, links
and inputs all share the `[data-toolbar-item]` attribute.

### Orientation

```css
[data-toolbar-root][data-orientation="horizontal|vertical"] {
  /* styles per orientation */
}

/* separators use the opposite orientation of the toolbar */
[data-toolbar-separator][data-orientation="vertical"] {
  width: 1px;
}

[data-toolbar-separator][data-orientation="horizontal"] {
  height: 1px;
}
```

### Focused state

Use native focus selectors. `:focus-visible` targets the focused item and
`:focus-within` targets the root while focus is inside.

```css
[data-toolbar-root]:focus-within {
  /* styles for the root while an item is focused */
}

[data-toolbar-item]:focus-visible {
  /* styles for the focused item */
}
```

### Disabled state

```css
[data-toolbar-root][data-disabled] {
  /* styles when the whole toolbar is disabled */
}

[data-toolbar-group][data-disabled] {
  /* styles for a disabled group */
}

[data-toolbar-item][data-disabled] {
  /* styles for a disabled item */
}

/* disabled, but still reachable with the arrow keys */
[data-toolbar-item][data-focusable-when-disabled] {
  /* ... */
}
```

Toggle group items inside a toolbar keep their own attributes. See the
[toggle group styling guide](/components/toggle-group#styling-guide).

## Accessibility

Follows the
[WAI-ARIA Toolbar pattern](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/) —
the toolbar is a single tab stop and arrow keys move focus between items.

The first time the toolbar receives focus, it moves focus to the first item.
After that, the last focused item keeps the tab stop, so tabbing back returns to
it.
