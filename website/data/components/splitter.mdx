A splitter creates resizable layouts with horizontal or vertical panels

<Resources pkg="@zag-js/splitter" />

<Showcase id="Splitter" />

**Features**

- Built with flexbox for flexible layout and SSR
- Supports horizontal and vertical panels
- Supports multiple panels and resize handles
- Supports collapsible panels
- Supports panel constraints like min and max sizes
- Programmatic control of panel sizes
- Implements the
  [Window Splitter pattern](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/)
  for accessibility and keyboard controls
- Supports multi-drag at handle intersections via a shared registry

## Usage

<CodeSnippet id="splitter/usage.mdx" />

### Initial size

To set the initial size of the splitter panels, use the `defaultSize` property.
Ensure the `defaultSize` totals to `100`.

> Note: The splitter only supports setting percentage values.

<Example id="SplitterDefaultSize">

```tsx {3}
const service = useMachine(splitter.machine, {
  // ...
  defaultSize: [40, 60],
})
```

</Example>

### Controlled panel sizes

Use `size` and `onResize` for controlled layouts.

<Example id="SplitterControlled">

```tsx
const service = useMachine(splitter.machine, {
  panels,
  size,
  onResize(details) {
    setSize(details.size)
  },
})
```

</Example>

### Resize events

When the resize trigger is dragged, the `onResize`, `onResizeStart` and
`onResizeEnd` callbacks are invoked.

<Example id="SplitterResizeEvents">

```tsx {3-10}
const service = useMachine(splitter.machine, {
  // ...
  onResize(detail) {
    console.log("resize", detail)
  },
  onResizeStart() {
    console.log("resize start")
  },
  onResizeEnd(detail) {
    console.log("change end", detail)
  },
})
```

</Example>

### Orientation

By default, the splitter is assumed to be horizontal. To change the orientation
to vertical, set the `orientation` property in the machine's context to
`vertical`.

<Example id="SplitterVertical">

```tsx {3}
const service = useMachine(splitter.machine, {
  // ...
  orientation: "vertical",
})
```

</Example>

### Constraints

Use the `panels` property to specify constraints like `minSize` and `maxSize`
for the splitter panels.

<Example id="SplitterConstraints">

```tsx {3-6}
const service = useMachine(splitter.machine, {
  // ...
  panels: [
    { id: "a", minSize: 20, maxSize: 80 },
    { id: "b", minSize: 20, maxSize: 80 },
  ],
})
```

</Example>

### Keyboard step

Use `keyboardResizeBy` to set how much each arrow key press resizes, as a
percentage of the group.

<Example id="SplitterKeyboard">

```tsx
const service = useMachine(splitter.machine, {
  panels,
  keyboardResizeBy: 5,
})
```

</Example>

### Collapsed size

Set the `collapsedSize` and `collapsible` of a panel to specify the collapsed
size of the panel.

> For best results, ensure you also set the `minSize` of the panel

<Example id="SplitterCollapsible">

```tsx {4}
const service = useMachine(splitter.machine, {
  // ...
  panels: [
    { id: "a", collapsible: true, collapsedSize: 5, minSize: 10, maxSize: 20 },
    { id: "b", minSize: 50 },
  ],
})
```

</Example>

This allows the user to drag the splitter to collapse the panel to the
`collapsedSize`. `Enter` on the handle collapses the panel, and pressing it
again restores its earlier size.

### Collapse threshold

A drag collapses or expands a panel once it passes halfway between
`collapsedSize` and `minSize`. Set `collapsedThreshold` to change the distance.

```tsx
panels: [
  {
    id: "a",
    collapsible: true,
    collapsedSize: 5,
    minSize: 15,
    collapsedThreshold: 2,
  },
]
```

### Reset with double-click

Double-clicking a handle resets the panel before it to its default size.

### Disabling resize

Set `disabled` on the machine, a panel, or a handle.

- **Machine**: turns off every handle. The API still works.
- **Panel**: locks its size, including from the API.
- **Handle**: turns off that handle. Its panels can still change through others.

Disabled handles can't be focused or dragged, and get `aria-disabled`.

```tsx
const service = useMachine(splitter.machine, {
  panels: [{ id: "a", disabled: true }, { id: "b" }],
})

<div {...api.getResizeTriggerProps({ id: "a:b", disabled: true })} />
```

### Collapse events

When the splitter panel is collapsed, the `onCollapse` callback is invoked.
Alternatively, the `onExpand` callback is invoked when the panel is expanded.

<Example id="SplitterCollapseEvents">

```tsx {3-8}
const service = useMachine(splitter.machine, {
  // ...
  onCollapse(detail) {
    console.log("collapse", detail)
  },
  onExpand(detail) {
    console.log("expand", detail)
  },
})
```

</Example>

### Programmatic control

Use the connected API to resize, collapse, or expand panels from code.

<Example id="SplitterProgrammatic">

```tsx
api.setSizes([30, 70])
api.resizePanel("a", 40)
api.resizePanel("a", "200px")
api.collapsePanel("a")
api.expandPanel("a")
api.resetSizes()
```

</Example>

### Registry multi-drag

When you have nested splitters (e.g. horizontal and vertical), users can drag at
handle intersections to resize both directions simultaneously. Use
`splitter.registry()` to coordinate multiple splitter instances.

```tsx
import * as splitter from "@zag-js/splitter"

// Create a shared registry (once, at the layout level)
const registry = splitter.registry()
```

Pass the `registry` to each splitter machine that should participate in
multi-drag:

<Example id="SplitterRegistry">

```tsx
const horizontalService = useMachine(splitter.machine, {
  panels: [{ id: "left" }, { id: "right" }],
  registry,
})

const verticalService = useMachine(splitter.machine, {
  orientation: "vertical",
  panels: [{ id: "top" }, { id: "bottom" }],
  registry,
})
```

</Example>

When a user drags near the intersection of two resize handles, the registry
detects both handles and resizes them together. The registry also manages the
cursor globally during intersection dragging.

### Registry options

The `splitter.registry()` function accepts optional configuration:

<Example>

```tsx
const registry = splitter.registry({
  // Nonce for injected cursor stylesheet (CSP compliance)
  nonce: "abc123",
  // Hit area margins for intersection detection
  hitAreaMargins: {
    coarse: 20, // touch devices (default: 15)
    fine: 10, // pointer devices (default: 5)
  },
})
```

</Example>
