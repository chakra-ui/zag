An accessible dropdown and context menu that is used to display a list of
actions or options that a user can choose

<Resources pkg="@zag-js/menu" />

<Showcase id="Menu" />

**Features**

- Supports items, labels, groups of items
- Focus is fully managed using `aria-activedescendant` pattern
- Typeahead to allow focusing items by typing text
- Keyboard navigation support including arrow keys, home/end, page up/down
- Supports multiple triggers sharing a single menu instance

## Usage

<CodeSnippet id="menu/usage.mdx" />

### Item selection

When a menu item is clicked, the `onSelect` callback is invoked.

<Example id="MenuSelection">

```tsx {3-6}
const service = useMachine(menu.machine, {
  onSelect(details) {
    // details => { value: string }
    console.log("selected value is ", details.value)
  },
})
```

</Example>

### Open state changes

When a menu is opened or closed, the `onOpenChange` callback is invoked.

<Example id="MenuOpenChange">

```tsx {3-6}
const service = useMachine(menu.machine, {
  onOpenChange(details) {
    // details => { open: boolean, reason?: OpenChangeReason }
    console.log("open state is ", details.open)
  },
})
```

</Example>

`details.reason` says what caused the change.

| Reason             | Meaning                                               |
| ------------------ | ----------------------------------------------------- |
| `trigger-click`    | The trigger was pressed by pointer or `Enter`/`Space` |
| `arrow-key`        | An arrow key opened or closed the menu                |
| `context-menu`     | The context trigger was right-clicked or long-pressed |
| `trigger-hover`    | The pointer hovered, or left, a trigger or submenu    |
| `sibling-open`     | Another menu in the menubar opened                    |
| `item-select`      | An item was selected                                  |
| `escape-key`       | The user pressed `Esc`                                |
| `interact-outside` | The user pressed outside the menu                     |
| `focus-outside`    | Focus moved outside                                   |
| `tab-key`          | `Tab` moved focus out of the menu                     |
| `script`           | Changed programmatically, such as `setOpen`           |

### Opening on hover

A menu opens by click or keyboard. To open it on hover yourself, pass
`trigger-hover` to `setOpen`. The menu then opens and closes without moving
focus, so a user typing elsewhere isn't interrupted.

```tsx
<div
  onPointerEnter={() => api.setOpen(true, "trigger-hover")}
  onPointerLeave={() => api.setOpen(false, "trigger-hover")}
>
  <button {...api.getTriggerProps()}>Actions</button>
  <div {...api.getPositionerProps()}>{/* content */}</div>
</div>
```

### Controlled open

Use `open` and `onOpenChange` to control visibility externally.

<Example id="MenuControlled">

```tsx
const service = useMachine(menu.machine, {
  open,
  onOpenChange(details) {
    setOpen(details.open)
  },
})
```

</Example>

</Example>

### Item groups

When you have many menu items, it can help to group related options:

- Wrap the menu items within an element.
- Spread `api.getItemGroupProps(...)` props on the group element, providing an
  `id`.
- Render a label for the menu group, providing the `id` of the group element.

<Example id="MenuGroups">

```tsx
//...
<div {...api.getContentProps()}>
  {/* ... */}
  <hr {...api.getSeparatorProps()} />
  <p {...api.getItemGroupLabelProps({ htmlFor: "account" })}>Accounts</p>
  <div {...api.getItemGroupProps({ id: "account" })}>
    <button {...api.getItemProps({ value: "account-1" })}>Account 1</button>
    <button {...api.getItemProps({ value: "account-2" })}>Account 2</button>
  </div>
</div>
//...
```

</Example>

### Checkbox and radio items

To use checkbox or radio option items, you'll need to:

- Add a `value` property to the machine's context whose value is an object
  describing the state of the option items.
- Use the `api.getOptionItemProps(...)` function to get the props for the option
  item.

A common requirement for the option item that you pass the `name`, `value` and
`type` properties.

- `type` — The type of option item. Either `"checkbox"` or `"radio"`.
- `value` — The value of the option item.
- `checked` — The checked state of the option item.
- `onCheckedChange` — The callback to invoke when the checked state changes.

### Default open

Use `defaultOpen` to start with the menu opened in uncontrolled mode.

<Example>


</Example>

### Keep open on select

Set `closeOnSelect` to `false` to keep the menu open after selecting an item.

<Example id="MenuKeepOpen">

```tsx
const service = useMachine(menu.machine, {
  closeOnSelect: false,
})
```

</Example>

### Managing focus

Set `initialFocusEl` to choose the element focused when the menu opens, and
`finalFocusEl` for when it closes. Return `false` from `initialFocusEl` to leave
focus where it is.

```tsx
const service = useMachine(menu.machine, {
  initialFocusEl: () => document.getElementById("menu-search"),
  finalFocusEl: () => document.getElementById("editor"),
})
```

### Positioning

Use `positioning` to configure menu placement.

<Example id="MenuPositioning">

```tsx
const service = useMachine(menu.machine, {

```

</Example>

### Multiple triggers

A single menu instance can be shared across multiple trigger elements. Pass a
`value` to `getTriggerProps` to identify each trigger.

<Example>

```tsx
const service = useMachine(menu.machine, {
  onTriggerValueChange({ value }) {
    console.log("active trigger:", value)
  },
})

const api = menu.connect(service, normalizeProps)

return (
  <>
    <button {...api.getTriggerProps({ value: "file" })}>File</button>
    <button {...api.getTriggerProps({ value: "edit" })}>Edit</button>
    <div {...api.getPositionerProps()}>
      <div {...api.getContentProps()}>
        {/* Menu items based on api.triggerValue */}
      </div>
    </div>
  </>
)
```

</Example>

When the menu is open and a different trigger is activated, it repositions
without closing. `aria-expanded` is scoped to the active trigger, and focus
returns to the correct trigger on close.

### Hidden label

If you do not render a visible label, provide `aria-label`.

<Example>

```tsx
const service = useMachine(menu.machine, {
  "aria-label": "Actions",
})
```

</Example>

### Infinite scroll

Compose menu with [`async-list`](/utilities/async-list) and
[`infinite-scroll`](/utilities/infinite-scroll) to load pages on open and fetch
the next page as the user scrolls.

- Keep `autoReload: false` so nothing fetches until the menu opens.
- Call `listApi.reload()` once from `onOpenChange` on the first open.
- Render a `LoadMore` child (owning `infinite-scroll.machine`) only while the
  menu is open, and keep its sentinel out of `getItemProps` so keyboard
  navigation skips it.

Install the extra packages alongside the menu package:

```bash
npm install @zag-js/async-list @zag-js/infinite-scroll
```

### Virtualized items

When only some items are rendered, pass the full list as a `collection` so the
arrow keys, `Home`, `End`, and typeahead can reach the rest. `scrollToIndexFn`
scrolls the highlighted item into view.

```tsx
const collection = menu.collection({ items })

const service = useMachine(menu.machine, {
  collection,
  scrollToIndexFn(details) {
    virtualizer.scrollToIndex(details.index)
  },
})
```

### Nested menus

A nested menu is a second menu machine. Link the two, then render the child's
trigger inside the parent with `api.getTriggerItemProps(...)`.

- `setParent(...)` - Registers the parent menu on the child menu.
- `setChild(...)` - Registers the child menu on the parent menu.

<Showcase id="NestedMenu" />

Use `positioning` on the child to place the submenu.

```tsx
const service = useMachine(menu.machine, {
  positioning: { placement: "right-start" },
})
```

```css
  --arrow-size: 20px;
  --arrow-background: red;
}
```
