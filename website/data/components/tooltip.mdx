A tooltip is a short message that appears when the user hovers or focuses an
element

<Resources pkg="@zag-js/tooltip" />

<Showcase id="Tooltip" />

**Features**

- Show tooltip on hover and focus
- Hide tooltip on Esc, click, pointer down, or scroll
- Only one tooltip shows at a time
- Labeling support for screen readers via `aria-describedby`
- Custom show and hide delay support
- Matches native tooltip behavior with delay on hover of first tooltip and no
  delay on subsequent tooltips
- Supports multiple triggers sharing a single tooltip instance

## Usage

To get tooltip working, you'll need to:

- Set up the tooltip portal (shared container for tooltips)
- Add `triggerProps` and `tooltipProps` to the right elements

<CodeSnippet id="tooltip/usage.mdx" />

### Timings

By default, the tooltip opens after `400ms` and closes after `150ms`. You can
customize this by passing the `openDelay` and `closeDelay` context properties.

<Example id="TooltipTimings">

```tsx {2-3}
const service = useMachine(tooltip.machine, {
  openDelay: 500,
  closeDelay: 200,
})
```

</Example>

### Placement

The tooltip uses [floating-ui](https://floating-ui.com/) for dynamic
positioning. You can change the placement of the tooltip by passing the
`positioning.placement` context property to the machine.

<Example id="TooltipPlacement">

```tsx {2-4}
const service = useMachine(tooltip.machine, {
  positioning: {
    placement: "bottom-start",
  },
})
```

</Example>

### Arrow

To render an arrow within the tooltip, use the `api.getArrowProps()` and
`api.getArrowTipProps()`.

<Example id="TooltipArrow">

```tsx {6-8}
//...
const api = tooltip.connect(service, normalizeProps)
//...
return (
  <div {...api.getPositionerProps()}>
    <div {...api.getArrowProps()}>
      <div {...api.getArrowTipProps()} />
    </div>
    <div {...api.getContentProps()}>{/* ... */}</div>
  </div>
)
//...
```

</Example>

### Dismiss behavior

Tooltips close on Escape, click, pointer down, and scroll by default. Configure
these with `closeOnEscape`, `closeOnClick`, `closeOnPointerDown`, and
`closeOnScroll`.

<Example id="TooltipDismiss">

```tsx {2-5}
const service = useMachine(tooltip.machine, {
  closeOnEscape: false,
  closeOnClick: false,
  closeOnPointerDown: false,
  closeOnScroll: false,
})
```

</Example>

### Interactive tooltip

Set the `interactive` context property to `true` to make the tooltip
interactive.

When a tooltip is interactive, it remains open as the pointer moves from the
trigger into the content.

<Example id="TooltipInteractive">

```tsx {2}
const service = useMachine(tooltip.machine, {
  interactive: true,
})
```

</Example>

### Open state changes

When the tooltip is opened or closed, the `onOpenChange` callback is invoked.

<Example id="TooltipOpenChange">

```tsx {2-7}
const service = useMachine(tooltip.machine, {
  onOpenChange(details) {
    // details => { open: boolean }
    console.log(details.open)
  },
})
```

</Example>

### Multiple triggers

A single tooltip instance can be shared across multiple trigger elements. Pass a
`value` to `getTriggerProps` to identify each trigger.

<Example id="TooltipMultipleTriggers">

```tsx
const service = useMachine(tooltip.machine, {
  onTriggerValueChange({ value }) {
    console.log("active trigger:", value)
  },
})

const api = tooltip.connect(service, normalizeProps)

return (
  <>
    <button {...api.getTriggerProps({ value: "bold" })}>B</button>
    <button {...api.getTriggerProps({ value: "italic" })}>I</button>
    <div {...api.getPositionerProps()}>
      <div {...api.getContentProps()}>
        {api.triggerValue === "bold" ? "Bold" : "Italic"}
      </div>
    </div>
  </>
)
```

</Example>

When hovering a different trigger while the tooltip is open, it repositions
without closing. `aria-describedby` is scoped to the active trigger.

### Animating between triggers

To animate the switch from one trigger to another, render a content per trigger
inside the viewport, and wrap the viewport and each content in
[Presence](/components/presence). Keep the arrow next to the viewport.

```tsx
<div {...api.getPositionerProps()}>
  <div {...api.getArrowProps()}>
    <div {...api.getArrowTipProps()} />
  </div>
  <Presence {...api.getViewportProps()}>
    {items.map((item) => (
      <Presence
        key={item.value}
        {...api.getContentProps({ value: item.value })}
      >
        {item.label}
      </Presence>
    ))}
  </Presence>
</div>
```

The viewport is the tooltip box: it opens and closes, and takes the size of the
current content through `--viewport-width` and `--viewport-height`. Each content
gets `data-state="open"` while its trigger is the current one.

While switching, the positioner and viewport get `data-transitioning`, and the
viewport and contents get `data-activation-direction`: where the new trigger
sits relative to the previous one, on both axes (`right`, `left up`, ...). It's
also available as `api.activationDirection`.

```css
[data-tooltip-positioner][data-transitioning] {
  transition: transform 250ms ease;
}

[data-tooltip-viewport] {
  overflow: clip;

  &[data-transitioning] {
    transition:
      width 250ms ease,
      height 250ms ease;
  }
}

[data-tooltip-content] {
  /* Laid out at its own size, so the viewport can measure it */
  position: absolute;
  top: 0;
  left: 0;
  width: max-content;
}
```

See the [popover](/components/popover#animating-between-triggers) for sliding
the contents in the direction of the new trigger.

### Controlled open

Use `open` and `onOpenChange` for controlled usage.

<Example id="TooltipControlled">

```tsx
const service = useMachine(tooltip.machine, {
  open,
  onOpenChange(details) {
    setOpen(details.open)
  },
})
```

</Example>

### Programmatic open

Use the connected API for imperative control.

<Example id="TooltipProgrammatic">

```tsx
api.setOpen(true)
```

</Example>

## Styling

### Arrow styling

When using arrows within the menu, you can style it using css variables.

```css
[data-tooltip-arrow] {
  --arrow-size: 20px;
  --arrow-background: red;
}
```
