An accordion is a vertically stacked set of interactive headings containing a
title, content snippet, or thumbnail representing a section of content.

<Resources pkg="@zag-js/accordion" />

<Showcase id="Accordion" />

**Features**

- Full keyboard navigation
- Supports single and multiple expanded items
- Supports keeping one item always open
- Supports horizontal and vertical orientation

### Multiple open

Set `multiple` to `true` to allow more than one expanded item at a time.

<Example id="AccordionMultiple">

```tsx {2}
const service = useMachine(accordion.machine, {
  multiple: true,
})
```

</Example>

### Initial value

Set `defaultValue` to define expanded items on first render.

<Example id="AccordionInitialValue">

```tsx
// multiple mode
const service = useMachine(accordion.machine, {
  multiple: true,
  defaultValue: ["home", "about"],
})

// single mode
const service = useMachine(accordion.machine, {
  defaultValue: ["home"],
})
```

</Example>

### Keep one open

Items can be closed by clicking them again. Set `collapsible` to `false` to
always keep one item open.

> Note: If `multiple` is `true`, items are always collapsible.

<Example id="AccordionKeepOpen">

```tsx {2}
const service = useMachine(accordion.machine, {
  collapsible: false,
})
```

</Example>

### Value changes

When the accordion value changes, the `onValueChange` callback is invoked.

<Example id="AccordionValueChange">

```tsx {2-5}
const service = useMachine(accordion.machine, {
  onValueChange(details) {
    // details => { value: string[] }
    console.log("selected accordion:", details.value)
  },
})
```

</Example>

### Focus changes

Use `onFocusChange` to react when keyboard focus moves between item triggers.

<Example id="AccordionFocusChange">

```tsx
const service = useMachine(accordion.machine, {
  onFocusChange(details) {
    // details => { value: string | null }
    console.log("focused item:", details.value)
  },
})
```

</Example>

### Horizontal orientation

Set `orientation` to `horizontal` when rendering items side by side.

<Example id="AccordionHorizontal">

```tsx {2}
const service = useMachine(accordion.machine, {
  orientation: "horizontal",
})
```

</Example>

### Disabled items

To disable a specific accordion item, pass the `disabled: true` property to the
`getItemProps`, `getItemTriggerProps` and `getItemContentProps`.

When an accordion item is disabled, it is skipped from keyboard navigation and
can't be interacted with.

<Example id="AccordionDisabled">

```tsx
//...
<div {...api.getItemProps({ value: "item", disabled: true })}>
  <h3>
    <button {...api.getItemTriggerProps({ value: "item", disabled: true })}>
      Trigger
    </button>
  </h3>
  <div {...api.getItemContentProps({ value: "item", disabled: true })}>
    Content
  </div>
</div>
//...
```

</Example>

You can also disable the entire accordion by setting `disabled` on the machine.

```tsx {2}
const service = useMachine(accordion.machine, {
  disabled: true,
})
```

### Find-in-page

Set `hiddenUntilFound` to keep closed items searchable with the browser's
find-in-page. When a match is found inside a closed item, the item expands and
the match shows without the open animation.

<Example id="AccordionHiddenUntilFound">

```tsx {2}
const service = useMachine(accordion.machine, {
  hiddenUntilFound: true,
})
```

</Example>

In controlled mode, the expansion goes through `onValueChange`. If `value` isn't
updated, the item is hidden again.

> With server-side rendering, frameworks like React render `hidden` as a
> boolean, so closed content ships as `hidden=""` and only becomes searchable
> after hydration.

## Styling

### Find-in-page and CSS resets

`hiddenUntilFound` renders closed content with `hidden="until-found"`. A reset
like `[hidden] { display: none }` overrides it and stops find-in-page from
searching closed items. Exclude `until-found` from the rule:

```css
[hidden]:not([hidden="until-found"]) {
  display: none;
}
```
