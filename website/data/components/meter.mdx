Shows a measurement inside a known range, like storage used or battery left; for
task progress, use [`progress`](/components/progress)

<Resources pkg="@zag-js/meter" />

<Showcase id="Meter" />

**Features**

- Supports controlled and uncontrolled values
- Supports minimum and maximum values
- Computes HTML `low` / `high` / `optimum` regions
- Supports horizontal and vertical orientation
- Localized value formatting

## Usage

> Pass a unique `id` to `useMachine` so the label id used by `aria-labelledby`
> stays unique. Override it with `ids.label` when the label lives outside the
> machine.

<CodeSnippet id="meter/usage.mdx" />

The root carries `role="meter"`, `aria-valuemin`, `aria-valuemax`,
`aria-valuenow`, `aria-valuetext`, and `aria-labelledby`. The visible value text
is `aria-hidden` because assistive tech already reads `aria-valuetext`.

### Initial value

Use `defaultValue` for uncontrolled state, or `value` for controlled state. When
neither is passed, the value defaults to `min`.

<Example id="MeterSetValue">

```tsx {2}
const service = useMachine(meter.machine, {
  defaultValue: 70,
})
```

</Example>

Use `api.setValue`, `api.setToMin`, and `api.setToMax` to update it.

```tsx
api.setValue(40)
api.setToMin()
api.setToMax()
```

### Value changes

Use `onValueChange` to react to updates.

<Example id="MeterValueChange">

```tsx
const service = useMachine(meter.machine, {
  onValueChange(details) {
    // details => { value: number }
    console.log(details.value)
  },
})
```

</Example>

### Min and max

By default the meter uses `min` `0` and `max` `100`. Values outside the range
are clamped.

<Example id="MeterMinMax">

```tsx {2-3}
const service = useMachine(meter.machine, {
  min: 0,
  max: 1000,
})
```

</Example>

### Thresholds

Pass `low`, `high`, and `optimum`. They default the same way the HTML element
does: `low` to `min`, `high` to `max`, `optimum` to the midpoint. The machine
exposes the resulting region as `valueState`: `optimal`, `suboptimal`, or
`least-optimal`.

- If `optimum` is below `low`, a smaller value is better (disk usage).
- If `optimum` is above `high`, a larger value is better (battery).
- If `optimum` sits between `low` and `high`, that band is preferred.

<Example id="MeterThresholds">

```tsx
const service = useMachine(meter.machine, {
  defaultValue: 70,
  low: 60,
  high: 85,
  optimum: 10,
})
```

</Example>

Style the fill with `data-state`:

```css
[data-meter-indicator][data-state="optimal"] {
  background: green;
}

[data-meter-indicator][data-state="suboptimal"] {
  background: gold;
}

[data-meter-indicator][data-state="least-optimal"] {
  background: red;
}
```

### Value text

Use `translations.value` when the formatted number is not enough for assistive
tech.

<Example id="MeterValueText">

```tsx
const service = useMachine(meter.machine, {
  translations: {
    value: ({ value, max }) => `${value} of ${max} gigabytes used`,
  },
})
```

</Example>

Render the `valueText` part if you also want that string on screen.

```tsx
<div {...api.getValueTextProps()}>{api.valueAsString}</div>
```

### Percent formatting

`formatOptions` defaults to `{ style: "percent" }`. Pass a different
`Intl.NumberFormat` style when the raw value should be shown. `percentAsString`
always shows a percent.

<Example id="MeterLocale">

```tsx
const service = useMachine(meter.machine, {
  locale: "fr-FR",
  formatOptions: { style: "unit", unit: "gigabyte" },
})
```

</Example>

### Vertical orientation

Set `orientation` to `vertical` for a vertical meter.

<Example id="MeterVertical">

```tsx
const service = useMachine(meter.machine, {
  orientation: "vertical",
})
```

</Example>
