**Features**

- List, table, grid, window, and masonry virtualizers
- Prop getters that position, measure, and label items in any framework
- Items measured automatically when their size depends on their content
- Scroll-to-index that scrolls only as far as needed
- Stable keys for prepend/chat flows

## Installation

```bash
npm install @zag-js/virtualizer
```

## How it works

Every virtualizer follows the same loop:

1. Create it with a size for its items: `itemSize` when every item is the same,
   or `estimatedItemSize` when items are sized by their content.
2. Call `init(element)` with the scroll container. The virtualizer listens to
   its scroll and finds rendered items itself.
3. Spread the prop getters: `getRootProps()` on the scroll container,
   `getContentProps()` on the element holding the items, and
   `getItemProps(item)` on each item from `getVirtualItems()`.
4. Call `updateOptions` when inputs such as `count` change, and `destroy()` on
   unmount.

Subscribe with `virtualizer.subscribe` and `virtualizer.getSnapshot` (stable
class fields, so they work with `useSyncExternalStore`). Pass your adapter's
`normalizeProps` and a unique `id` when creating a virtualizer, so the props
match your framework and server-rendered markup.

`updateOptions` compares arrays and objects by content and keeps the latest
callbacks without re-rendering, so you can pass options fresh on every render.

## List virtualizer

Use `ListVirtualizer` for feeds, logs, and chat timelines.

<CodeSnippet id="virtualizer/list-virtualizer-usage.mdx" />

`getVirtualItems()` returns `index`, `key`, `start`, `end`, `size`, `isVisible`,
and `isRetained` for each item to render. Horizontal lists use
`orientation: "horizontal"` and `dir: "ltr" | "rtl"`.

**Item sizes.** Set `itemSize` when every item is the same size; items are then
never measured. Otherwise set `estimatedItemSize`, and items rendered with
`getItemProps` are measured as they mount and whenever they resize. A number is
refined with the average measured size, so the scrollbar settles early; a
function gives per-item estimates as-is. Call `remeasure()` after a change that
resizes items without changing the list, like a breakpoint or font swap. Set
`observeScrollElementSize: true` if the scrollport can resize.

**Root props.** `getRootProps()` makes the scroll container focusable for
keyboard scrolling, sets `data-empty` when there are no items, and exposes the
total size as `--total-size`, so a container can shrink to fit:

```css
.list {
  max-height: min(400px, var(--total-size));
}
```

**Trailing content.** Spread `getTrailingProps()` on a loading row or
end-of-list note. It's measured, added to the total, and placed after the last
item:

```tsx
<div {...virtualizer.getTrailingProps()}>Loading more…</div>
```

**Loading more.** `onEndReached` fires once each time the rendered range reaches
the end, and re-arms when it moves away or `count` grows. `endReachedThreshold`
fires it that many items earlier:

```ts
new ListVirtualizer({
  count: items.length,
  estimatedItemSize: 48,
  onEndReached: loadNextPage,
  endReachedThreshold: 10,
})
```

**Geometry.** `getItemMetrics(index)` returns `{ start, size, end }` for any
item, mounted or not. `getIndexAtOffset(offset)` maps a scroll offset back to an
index.

**Scrolling.**

```ts
virtualizer.scrollToIndex(120, { align: "center" })
virtualizer.scrollToIndex(0, { smooth: true })
virtualizer.scrollToOffset(2400)
virtualizer.getVisibleRange()
```

`align` is `"start"`, `"center"`, `"end"`, or `"auto"` (default). `"auto"`
scrolls only when the item isn't fully visible, to the nearest edge, like a
native listbox. Use it for keyboard navigation. Scrolling accounts for the
scroll container's CSS `padding` and `scroll-padding`. Non-smooth scrolls settle
after the target measures. `scrollPaddingStart` / `scrollPaddingEnd` reserve
space for sticky chrome; `scrollMargin` offsets a list that sits below other
content in the same scroll container.

**Sticky headers.** Pass `groups` and read `getStickyGroupHeader()` while
scrolling. `translateY` pushes the current header up as the next group
approaches.

```ts
const virtualizer = new ListVirtualizer({
  count: items.length,
  estimatedItemSize: 32,
  estimatedGroupHeaderSize: 28,
  groups: [
    { id: "a", startIndex: 0 },
    { id: "b", startIndex: 50, headerSize: 40 },
  ],
})

virtualizer.getStickyGroupHeader()
// { group, headerSize, translateY, offset }
```

Render each header inside its group's first item. `estimatedGroupHeaderSize` (a
number, or a function of the group and its index) is added to that item's
estimate unless the group sets `headerSize`.

**Prepend / chat.** Provide `indexToKey` and `keyToIndex`, then call
`prependItems(addedCount)` (or `updateOptions({ count })` with
`preserveScrollAnchor: true`). Use `shouldAdjustScrollOnSizeChange` when a size
change above the viewport should keep the user pinned.

## Tables

Use `TableVirtualizer` to virtualize a real `<table>`, so a `<colgroup>`, a
sticky `<thead>`, and table semantics keep working. It windows rows like
`ListVirtualizer`, with two spacer rows reserving the space of rows outside the
rendered range. The row body is sticky, so rows stay painted while rendering
catches up.

```tsx
const { virtualizer, ref } = useTableVirtualizer({
  count: rows.length,
  estimatedItemSize: 37,
})

<div ref={ref} {...virtualizer.getRootProps()} className="table-scroller">
  <table {...virtualizer.getTableProps()}>
    <thead {...virtualizer.getHeaderProps()}>{/* sticky header cells */}</thead>
    <tbody aria-hidden>
      <tr {...virtualizer.getRowSpacerProps("start")} />
    </tbody>
    <tbody {...virtualizer.getBodyProps()}>
      {virtualizer.getVirtualItems().map((item) => (
        <tr key={item.key} {...virtualizer.getRowProps(item)} aria-rowindex={item.index + 2}>
          {/* cells */}
        </tr>
      ))}
    </tbody>
    <tbody aria-hidden>
      <tr {...virtualizer.getRowSpacerProps("end")} />
    </tbody>
  </table>
</div>
```

The `<thead>` is measured, so rows scroll clear of it. Set `footerSize` for rows
after the table body, like a loading row. `getRowProps` keeps rows held by
`retainedIndexes` focusable but out of the table layout.

**Wide tables.** Set `columnCount` and `columnSize` (a number or a function of
the column index) to window columns too. The table switches to
`table-layout: fixed`, so widths come from the `<col>` elements. Render pinned
columns, a start spacer, the windowed columns, then an end spacer, in the
`<colgroup>` and in every row:

```tsx
const { virtualizer, ref } = useTableVirtualizer({
  count: rows.length,
  estimatedItemSize: 37,
  columnCount: columns.length,
  columnSize: (index) => columns[index].width,
  pinnedColumns: { start: 1 },
})

const virtualColumns = virtualizer.getVirtualColumns()
const pinned = virtualColumns.filter((column) => column.pinned === "start")
const windowed = virtualColumns.filter((column) => !column.pinned)

<tr {...virtualizer.getRowProps(item)}>
  {pinned.map((column) => (
    <th key={column.index} {...virtualizer.getCellProps(column)}>…</th>
  ))}
  <td {...virtualizer.getColumnSpacerProps("start")} />
  {windowed.map((column) => (
    <td key={column.index} {...virtualizer.getCellProps(column)}>…</td>
  ))}
  <td {...virtualizer.getColumnSpacerProps("end")} />
</tr>
```

Use `getColumnProps(column)` and `getColumnSpacerProps()` for the matching
`<col>` elements. Pinned columns are always rendered and `getCellProps` sticks
them to their edge; give pinned header cells a higher `z-index`.
`scrollToColumn(index, { align })` reveals a column clear of the pinned ones.
Column sizes must be known up front; a new `columnSize` resizes the columns.

## Grid virtualizer

Use `GridVirtualizer` when both rows and columns need windowing. It virtualizes
**rows** and renders cells inside each visible row; rows are measured, columns
use their estimates.

Jump with `scrollToCell(row, column)`, `scrollToRow(row)` or
`scrollToColumn(column)`. Each takes `align` (default `"auto"`) and `behavior`.
The range reports `startRow` / `endRow` and `startColumn` / `endColumn`.

## SSR

Seed the first paint to avoid hydration jumps:

```ts
new ListVirtualizer({
  id,
  count: items.length,
  estimatedItemSize: 56,
  initialRect: { width: 1024, height: 720 },
  initialOffset: 0,
  initialMeasurements: cachedMeasurements,
})
```

`initialMeasurements` accepts a `Map` or object (by key or index).
`disableScrollOnInit` leaves scroll restoration to the browser. Pass the same
`id` on the server and client, such as one from your framework's `useId`.

## Composition

Virtualize a component's list by merging its props with the virtualizer's, with
the component's last so its roles and focus handling win:

```tsx
const service = useMachine(combobox.machine, {
  collection,
  scrollToIndexFn(details) {
    virtualizer.scrollToIndex(details.index)
  },
})

<div ref={ref} {...mergeProps(virtualizer.getRootProps(), api.getListProps())}>
  <div {...virtualizer.getContentProps()}>
    {virtualizer.getVirtualItems().map((virtualItem) => {
      const item = items[virtualItem.index]
      return (
        <div
          key={virtualItem.key}
          {...mergeProps(virtualizer.getItemProps(virtualItem), api.getItemProps({ item }))}
        >
          {item.label}
        </div>
      )
    })}
  </div>
</div>
```

The same pattern works for select, listbox, menu, and tree view. Item props add
list roles with `aria-posinset` and `aria-setsize`; when items are layout
wrappers around elements with their own semantics, or rows of a grid, pass
`aria: false`.

Use `retainedIndexes` to keep focused items and `aria-activedescendant` targets
mounted outside the viewport without scrolling:

```ts
virtualizer.updateOptions({ retainedIndexes: [highlightedIndex] })
```

Works with list, window, and masonry virtualizers, including custom
`rangeExtractor` functions. Keep the set small, update indexes after filtering
or reordering, and pass `[]` to release items. Use `scrollToIndex` to reveal
them.

## Pitfalls

- Render items inside the element passed to `init`; items elsewhere (such as a
  portal) aren't measured.
- Merge your own styles with `mergeProps` instead of passing a separate `style`,
  which would replace the virtualizer's positioning.
- Give the scroll container a fixed `height` or `max-height`. In development,
  the virtualizer warns when it grows to fit every item.
- `transform: scale(...)` on the scroll container is unsupported.
- Always call `destroy()` to release observers and listeners.
